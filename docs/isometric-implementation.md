# Изометрические карты — реализация первой версии

## Статус, 21.11.2026

Реализация ярусов, лестниц, изолированной видимости и графического редактора завершена локально по коду. Основание закрытия — явное указание владельца завершить реализацию без тестов. Свидетельства: статический разбор связанных исходников и хеши файлов в checkpoint. Исполнение, сборка, визуальная приёмка и применение новых SQL-миграций остаются неподтверждёнными; PASS не заявляется.

## Модель и совместимость

* `scenes.grid.isometric` хранит версию геометрии, общую аффинную калибровку, масштаб, до 16 ярусов, переходы и передние полигоны. `publishedFloorId` выбирает один транслируемый ярус; мастер выбирает свой просматриваемый ярус независимо.
* Логическая плоскость измеряется в клетках. Канонические размещения остаются пиксельными top-left записями: адаптер переводит точку ног в клетки. Оригинальный растр остаётся в экранной плоскости, а игровые слои проецируются на него. Преобразование обратно применяется к указателю.
* Ярус имеет постоянный UUID, имя мастера, границы, высоту в метрах, смещение по экрану и blocked-клетки. У тумана и рисунков появился `level_id`; токены используют существующий `level_id`. `null` сохраняет значение первого, базового яруса. Базовый UUID после настройки не переобозначается.
* Новая проекция включается только на сцене без токенов, рисунков и тумана. Обычные сцены и старые ISOMETRIC без явной калибровки идут через прежний ортогональный компонент. Математика обычного тумана сохраняет прежние границы по умолчанию; изометрия задаёт собственные логические границы яруса, включая отрицательные координаты. Предел логической плоскости согласован с действующими drawing API: ±32768 пикселей.

## Графический редактор мастера

В панели «Изометрия и ярусы»:

1. Указать на изображении начало сетки и по соседнему узлу для осей X/Y. Вырожденная калибровка отвергается при сохранении.
2. Создать ярусы, задать имена, границы, высоту и экранное смещение; выбрать публикуемый ярус.
3. Кликать клетки для переключения проходимости. Разметку яруса можно очистить.
4. Указать начало лестницы, выбрать другой ярус и указать конечную клетку. Создаётся явный двусторонний переход; список позволяет удалить его.
5. Обвести кликами переднюю часть здания, завершить полигон и указать высоту основания отдельным инструментом. Можно удалить отдельный полигон.

Редактор показывает настоящий ассет текущей сцены, сетку, blocked-клетки, концы лестниц и полигоны. JSON-ввод для этих операций не требуется. Черновик сохраняется с ревизией: конфликт не перетирает другую правку. Нельзя удалить ярус с существующими токенами, рисунками или туманом либо запереть токен новой маской.

## Перемещение и отображение

* `SceneMapRenderer` выбирает отдельное SVG-отображение. Upright-спрайт не сплющивается матрицей пола; проецируется точка ног. Mouse drag и WASD используют ту же плоскость. Мастер может провести выбранный токен через лестницу из её исходной клетки; после подтверждения открывается целевой ярус.
* Проверяется весь пересечённый путь, включая обе стороны угла; нельзя перескочить через стену длинным drag. Между ярусами требуется заданный переход с точными исходной и конечной клетками. Проверка — point-footprint, не коллизия всего изображения фигуры.
* Preview идёт через существующий канал с epoch/ревизией и серверной фильтрацией. Финальный ход подтверждает каноническая команда. Неопределённый результат удерживает pending до подтверждения/канонического обновления, предусмотрено ручное обновление страницы.
* Передние части зданий вырезаются из исходного фона и сортируются вместе с токенами по глубине ног/основания. Контур выбранного токена остаётся различимым. Права и туман определяются до отрисовки, а не через окклюзию.
* Каждый ярус показывает собственный туман, рисунки, штампы и текстуры. Подключены прямоугольник, кисть и полигон REVEAL/COVER; свободный рисунок; штамп и текстурная кисть. Линейка измеряет логические метры, состояние локальной линейки сбрасывается при смене яруса. Камера вписывает фон и текущую проекцию яруса.

## Серверные границы приватности

* Player snapshot содержит только опубликованный ярус, его разрешённые размещения, туман и рисунки. Другие ярусы, их имена, переходы и маски проходимости не сериализуются. Для корректного отображения legacy-null передаётся только булева подсказка текущего яруса, а не ID скрытого базового яруса.
* NPC видимость считается по клетке под ногами, а не высоте стоячего спрайта. Собственный управляемый токен сохраняет существующее исключение из тумана только внутри опубликованного яруса. Скрытый ярус не раскрывается даже контроллеру токена.
* У рисунков/декалей изометрии проверяется целиком раскрытый bbox в тумане соответствующего яруса. Их изображения попадают в asset ACL только вместе с разрешённой проекцией. Built-in stamp read также учитывает ярус/туман.
* Realtime token delivery повторяет опубликованный ярус и туман. Пересечение границы видимости вызывает каноническое обновление; скрытая конечная координата не передаётся ради удаления старого preview. Fog/drawing изменения изометрии доставляются через роль-фильтрованный snapshot, а не старый point event без контекста этажа.
* Создание, редактирование, копирование и удаление canvas-объектов проверяют ярус в транзакции; размещения и их дедупликация учитывают level ID. GM history сохраняет level ID при восстановлении. Старые PLAYER bulk/history команды без контекста яруса в изометрии отклоняются; обычные 2D-сцены сохраняют прежнее поведение.
* Старые shared cursor/ruler/ping пакеты без floor ID в изометрии отклоняются, чтобы они не раскрывали координаты скрытого яруса. Линейка и указатель в новом режиме локальные. Этот предел первой версии зафиксирован явно; прежний 2D realtime для них сохранён.

Фоновый растр — общий уже разрешённый ассет, не хранилище секретов мастера. Клиентская маска не делает ранее выданное изображение тайным и не отзывает прежние копии. Приватность новых ярусов относится к серверным данным/аннотациям/размещениям; тайные сведения нельзя помещать в общий исходный растр.

## Хранение и будущая поставка

* `0092_isometric_movement_guard.sql` вводит общий триггер token writes.
* `0093_isometric_floor_layers.sql` добавляет layer columns/indexes для fog/draw, расширяет общий триггер до ярусов и лестниц и проверяет layer ID при создании/восстановлении. Проверка действует для realtime, HTTP, bulk и истории, а не только нового клиента.
* `PUT /api/scenes/:id/isometric` требует GM, кампанию, ревизию и campaign/scene lock; пишет событие. Предыдущая SCENE_CANVAS история инвалидируется при смене политики, чтобы undo не удалил новую маску. Смена grid size/offset в обход изометрической настройки отвергается.

Новые миграции подготовлены, не применены. Для будущей поставки требуются согласованные API/web/contracts/db зависимости и обе миграции. Production-готовность, отсутствие runtime-регрессий и визуальное качество этой записью не утверждаются.
