# Текущее состояние Arken Space

Этот файл — короткий проверяемый снимок реализации и незакрытых gate. Он не
дублирует backlog: **Linear — единственный источник статусов, приоритетов и
acceptance criteria**, Git — источник фактической реализации, а датированные
checkpoint-файлы в `docs/` объясняют историю решений.

Последняя проверка: **29 августа 2026 года**.

## Идентичность ревизий

- Проверенный remote baseline `origin/main`:
  `128e807735d258181b24021a49fb66171f350023`.
- Непушенного локального пула больше нет: работа идёт ветками на задачу и
  сливается через pull request. Точный tip всегда берётся из
  `git rev-parse HEAD`, а не из этого файла.
- В production в рамках текущего пула ничего не развёртывалось. Развёртывание
  остаётся ручной процедурой и решением владельца.

## Что зафиксировано в Git

Arken Space — приватный web-first VTT для мастера и группы игроков. В `main`
зафиксированы авторизация кампании, PostgreSQL и миграции, realtime-сцены,
токены и туман произвольной формы, рисунки и линейка, персонажи и правила,
чат/активность/сюжет, броски, ресурсы и инвентарь, музыка, карты мира, заявки
игроков, стикеры и операторская обратная связь.

За точными инвариантами и границами следует обращаться к
[architecture.md](./architecture.md), а не к старым feature-checkpoint.

## Что изменилось с прошлой проверки

Двадцать пять pull request слиты в `main` после baseline `42c7ccc`. Перечисляются
не все — только то, что меняет способ работы с репозиторием:

- **Появился CI.** Три workflow (`checks`, `e2e`, `multiplayer`) гоняют те же
  гейты, что и локальный quality gate. Деплоя в CI нет. Подробности — в
  [development-guide.md](./development-guide.md#те-же-гейты-в-ci).
- **Появился гейт доступности.** `tests/e2e/accessibility.spec.ts` гоняет axe по
  тегам WCAG 2.1 AA; список исключений пуст и должен таким остаться (UIX-532).
- **Появился структурный вид тестов** — проверки формы кода, заведённые после
  дефектов, которые возвращались: `dismissible-popovers.test.ts` (UIX-531) и
  `action-hook-wire.test.ts` (UIX-532). Условия применимости — в
  [testing.md](./testing.md#структурные-тесты-правило-про-форму-кода).
- **Спеков на живом backend стало одиннадцать** вместо пяти; фикстура
  `campaign-fixture` с кампанией на тест — обязательна для каждого.
- **Фокус переживает чужую правку** (UIX-325 / UIX-532): неуправляемые поля
  больше не пересоздаются по ревизии, введённое и несохранённое не затирается.
- **Лента событий** закрепляется у дна при позднем росте содержимого (UIX-493) и
  возвращает слежение после ручной прокрутки (UIX-401, подтверждено замером).

## Гейты на текущем состоянии

Проверено на `128e807`:

- полный Vitest — **181 файл / 1342 теста PASS**;
- `pnpm typecheck`, `pnpm lint`, `pnpm format:check` — PASS;
- e2e и multiplayer — зелёные в CI на всех слитых pull request.

Числа проверяются автоматически там, где это возможно:
`tests/documentation-freshness.test.ts` сверяет с кодом проверяемые утверждения
[architecture.md](./architecture.md). Счётчики тестов в этом файле такой
проверкой не покрыты — сверяйте прогоном, а не доверием.

## Открытые gates

- **Человеческая репетиция сессии GM + 6** и production release gate остаются
  открытыми. Готовность production нельзя выводить из unit/typecheck/build.
- **UIX-408 / UIX-409 / UIX-450** остаются незакрытыми: не выполнено
  before/after measurement на одной изолированной копии дампа. Скрипт замера не
  запускался, значения не выдумывались. Порядок действий —
  [measurement-runbook-2026-08-24.md](./measurement-runbook-2026-08-24.md).
- **UIX-475** — автопрокрутка после правки ресурсов: синтетически не
  воспроизводится, кандидат «изменение высоты ленты» снят замером. Нужны
  сведения от мастера.

## Известные границы

- Direct messages намеренно не имеют текущей UI-точки входа до редизайна
  **UIX-365**; privacy/API-контракты нельзя ослаблять ради старого E2E.
- Следующий этап декомпозиции `App.tsx` не начинается без повторных измерений;
  выполненные этапы и критерии описаны в
  [app-tsx-decomposition-plan.md](./app-tsx-decomposition-plan.md).
- Полный recurring-session acceptance остаётся отдельным release gate. Нельзя
  выводить готовность production только из unit/typecheck/build.
