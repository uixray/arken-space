# UIX-325 — inventory focus diagnostics checkpoint

## Decision

The application contains no handler or synthetic keyboard path that opens native browser Find in Page. The current leading hypothesis is an external Ctrl+F chord generated by Punto Switcher or another OS/browser integration.

Do not suppress Ctrl+F globally. Instead, the application now:

- ignores editable controls and IME composition in application-level undo and workspace-close shortcuts;
- exposes an opt-in, in-memory diagnostic ring buffer that never records entered text;
- records only event type, non-printable key name, physical code, modifiers, composition state and generic target tag/role.

## Local reproduction

1. Open the local build with `?input-diagnostics=1`.
2. Test the inventory field in Chrome and Firefox with:
   - Punto Switcher enabled and disabled;
   - Russian and English layouts;
   - ordinary typing and layout switching.
3. Immediately after unexpected Find in Page activation, run:
   `window.__arkenInputDiagnostics?.()`
4. Compare the last key/focus/composition events. Printable characters are stored as `printable`; field values and text are never captured.
