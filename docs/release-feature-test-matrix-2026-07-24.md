# UIX-271 вЂ” release feature inventory and manual test matrix

**Canonical date:** 2026-07-24  
**Candidate:** `b806d78` (merged PR #20)  
**Purpose:** manual release gate for implemented code only. This inventory comes from current contracts, HTTP/Socket routes, UI and checkpoints; it is not a production-deployment instruction.

## Test baseline

- Test with a GM, players A and B, and a third non-participant C in separate browser profiles. Retain IDs/screenshots in release evidence.
- **Reload** is a full browser reload; **reconnect** is a short offline/online cycle. **CAS** means repeat a write with its stale `revision`; expected result is an authoritative conflict reconciliation. **Replay** means repeat an accepted `actionId`; expected result is no duplicate durable mutation/message/media.
- Confirm authorization from the role-filtered `/api/bootstrap` response and protected content URL as well as from the UI. A hidden control alone is never proof of an ACL.
- Shared ground truth: `packages/contracts/src/index.ts` (`GameSnapshot`, Socket events), `apps/server/src/snapshot.ts`, `apps/server/src/realtime.ts`, and `apps/web/src/App.tsx`.

## Cross-feature release probes

1. **Projection:** With GM/A/B/C connected, create a GM-only canvas object, A private character/direct attachment, GM_ONLY chat, story draft and GM-only location. Inspect bootstrap and direct bytes: only authorized data may exist.
2. **Reload/reconnect:** Do one durable mutation in scenes, character, direct chat, story, world map, audio and generated token; reload A/B then force reconnect. Canonical state converges with no duplicate item and credible read/presence state.
3. **CAS/replay:** Use two GM tabs for a stale revision, and retry same actionId. Expected: conflict reconciliation, then exactly one canonical durable result.
4. **Accessibility/narrow layout:** Keyboard-test dialogs/workspaces/chat tabs/token generator: labels, focus, Escape/close/focus return, visible focus and modal layer above workspace.
5. **Operational boundary:** Capture `/healthz` and build/schema diagnostics as evidence only. Do **not** deploy, reset data, rotate real credentials, import Telegram material or upload unapproved media under UIX-271.

## Expected non-features and accepted risk

- Single campaign and active orthographic-2D scene; no isometric/3D, voice/video, offline mode, multi-active levels or travel calculation/per-player discovery.
- Fog is visual, not a confidentiality boundary; role-filtered snapshots and GM layers are.
- Story import is local-export review-first; skip dry-run/commit if no approved sample exists. Sticker catalog stays empty until separate asset approval.
- Accepted P2 from UIX-255: a hard kill between filesystem write and DB transaction can leave an orphan token file; ordinary failures are cleaned. Record it if observed; it is not a functional release blocker.
