# Фигурки токенов — первый пул UIX-715

Локальная реализация, без прогона тестов и проверки в браузере. Не опубликована.

## Подготовка изображения

- Один статичный квадратный PNG или WebP с альфа-каналом на кадр, без анимации.
- Один размер холста и одинаковый масштаб персонажа для всего набора.
- Не обрезайте прозрачные поля отдельно у разных кадров: при смене позы фигурка
  иначе будет прыгать. Опора по умолчанию — центр нижнего края `(0.5, 1)`.
- Рекомендуемые имена: `idle-front.png`, `idle-back.png`, `idle-left.png`,
  `idle-right.png`; аналогично `prone-*` и `flying-*`. Имя файла не определяет
  слот автоматически: мастер выбирает его в редакторе.
- Приложение не генерирует иллюстрации. Подготовленные владельцем изображения
  проходят отдельный серверный конвейер: максимум 64 млн входных пикселей,
  ограничение размера загрузки кампании, производная 512×512 WebP до 1 МиБ.
  Исходник этим маршрутом не сохраняется. Производная учитывается в медиаквоте.

## Загрузка и замена

В палитре токенов мастер открывает **Фигурка**, загружает кадры в нужные слоты,
при необходимости меняет общую точку опоры и нажимает **Сохранить набор**.
Обязателен только **Стоит — Спереди**. Остальные 11 слотов необязательны.
Предпросмотр показывает подготовленный кадр, а не исходный файл.

Загрузка файла ещё не меняет токен. Набор заменяется целиком с проверкой версии
определения: конкурентное изменение не перезаписывается молча. После конфликта
нужно закрыть редактор и открыть актуальную версию. Закрытие без сохранения
не удаляет уже загруженные файлы: они остаются в медиатеке.

**Вернуть круглый токен** снимает набор, не удаляя кадры и старый портрет.
Используемый кадр нельзя удалить или заменить через общий редактор файла.
Сначала снимите/замените все ссылающиеся на него наборы. Один кадр может быть
назначен нескольким слотам; два кадра одного слота запрещены.

## Как выбирается кадр

Направление хранится у размещения: вправо/влево по X, спереди/сзади по Y.
Положительный Y направлен вниз экрана. При равной диагонали побеждает X;
нулевое перемещение сохраняет направление. Расчёт происходит в БД после
авторитетного изменения координат, в том числе bulk/history/grid-transform.
Новые размещения без истории смотрят вперёд. Во время локального предпросмотра
перетаскивания направление не меняется до подтверждённого хода.

Приоритет поз: **Без сознания / Распластан → Лежит**, затем **Летит**, иначе
**Стоит**. Полёт не даёт высоты, прохода сквозь препятствия или игровых бонусов.
Отравление и обездвиженность остаются значками.

Резерв: текущая поза/направление → текущая поза/спереди → стоит/направление →
стоит/спереди → прежний круглый токен. Недоступный или не загрузившийся кадр
пропускается. Повторная загрузка страницы или новая версия URL сбрасывает
ошибку загрузки. Смена кадров без анимации; ручной поворот круглого портрета
не вращает фигурку. Логические координаты и правила перемещения не меняются.

## Технические границы и незавершённая проверка

Миграция `0069_token_sprite_facing.sql` обязательна: schema push без SQL-триггера
не обеспечивает расчёт направления. Миграция подготовлена, но не выполнялась.
Манифест содержит только UUID ассетов, не URL/пути. Сервер проверяет кампанию,
тип/размер производной и квитанцию именно текущего файла, блокируя конкурентную
замену/удаление. Игрок получает кадры только через существующие фильтры видимости.

Фигурки используют существующий ортографический рендерер, прямоугольную область
нажатия и общую точку опоры. Это не попиксельный выбор силуэта и не реализация
изометрии, ярусов или окклюзии UIX-714. Они остаются отдельным объёмом работ.

Не доказаны запуском: миграция, типизация/сборка, гонки изменения/удаления,
повтор загрузки при потере ответа, ACL/туман, браузерные мышь/тач/resize,
перезагрузка клиента и производительность на реальных сценах. Эти проверки
требуют отдельного разрешения владельца; чтение кода не является PASS.
