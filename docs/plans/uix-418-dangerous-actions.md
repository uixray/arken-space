# UIX-418 — акценты опасных действий

## Замер

- В `SceneManagerDialog` безопасное действие «Открыть для мастера» находится рядом с публикацией сцены для всех игроков; активная сцена уже имеет отдельное состояние «Показана игрокам».
- В палитре токенов удаление определения и всех его размещений находится рядом с «Настроить» и требует визуально более слабого веса.
- В рабочем интерфейсе списка сцен удаления сцены сейчас нет. Упоминание удаления в acceptance criteria не означает, что эту возможность нужно добавить в рамках задачи об иерархии действий.

## Scope

- Сделать «Открыть для мастера» основным действием карточки сцены.
- Оставить «Показать игрокам» вторичным действием и не показывать его для активной сцены; вместо него отображать состояние.
- Ослабить визуальный вес существующего удаления определения токена относительно соседнего созидательного действия.
- Не менять серверные маршруты, модель сцен и механику публикации.

## Решения

- Не добавлять подтверждение перед частым действием «Показать игрокам»: задача устраняет риск промаха через иерархию, а не через дополнительный диалог.
- Не добавлять отсутствующее удаление сцен. Если оно появится отдельной задачей, его опасность и подтверждение должны проектироваться там.
- Использовать существующие варианты Gravity UI и локальные классы компонентов, не вводя новый глобальный стиль опасных действий.
- Сохранить доступность действий по тексту и состояниям `disabled`; визуальный вес не должен быть единственным носителем смысла.

## Проверки

- Фокусный DOM-тест `SceneManagerDialog`: безопасное действие имеет основной вариант; активная сцена показывает статус и не предлагает повторную публикацию; неактивная сцена сохраняет вторичную публикацию.
- Фокусный DOM/структурный тест `TokenPalette`: удаление остаётся функциональным, но использует слабый опасный вариант и меньший размер относительно «Настроить».
- Диверсия нового теста: временно вернуть прежний вариант одного из действий и подтвердить изолированное падение целевого ожидания, затем восстановить код.
- После завершения общего пула: `pnpm format:check && pnpm lint && pnpm typecheck && pnpm build && pnpm test`; для изменённого UI-потока — оправданный браузерный smoke/E2E сценарий открытия менеджера сцен и палитры токенов.

## Чекпоинт

- **Решения:** «Открыть для мастера» использует основной action-вариант; публикация остаётся вторичной и не показывается для активной сцены; удаление определения токена стало компактным `flat-danger`. Отсутствующее удаление сцен и новый confirm не добавлялись.
- **Ревизия:** будет зафиксирована коммитом после финальной проверки.
- **Изменённые файлы:** `SceneManagerDialog.tsx`, `TokenPalette.tsx`, адресный стиль в `styles.css`, регрессия в `tests/e2e/concept.spec.ts`, этот план.
- **Проверки:** targeted ESLint и web typecheck PASS; Chromium scene/token сценарии 2/2 PASS; Prettier и `git diff --check` PASS.
- **Диверсия:** временное ожидание action-варианта у destructive token-кнопки изолированно уронило только новый token-тест 1/1; ожидание восстановлено, финальный прогон зелёный.
- **Блокеры:** нет. Production и Docker не используются.
- **Следующее действие:** commit, push, stacked PR и Linear In Review; merge/publication остаются отдельным релизным scope.
