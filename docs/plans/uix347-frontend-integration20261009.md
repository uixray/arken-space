# UIX-347 frontend integration map — 2026-10-09

Read-only source map for the next connected frontend pool. Backend contracts/schema/routes are in flight; names and shape below are current draft observations, not a freeze. No source changes or acceptance tests were performed in this mapping pass.

## Current integration seams

- **App composition and command ownership:** `apps/web/src/App.tsx`
  - `activeDrawings` (1020) selects current scene drawings from the server-projected `viewSnapshot`.
  - `activeCanvasVersion` (1059) fingerprints scene/fog/drawings/tokens and drives history-control refresh. Keep this derived from canonical state, not local prototype state.
  - `handleDrawingCreate` (1128) POSTs `/api/drawings`, then reconciles returned DTO into `snapshot.drawings`; `handleDrawingUpdate` (1295), `handleDrawingDelete` (1333), `handleDrawingCopy` (1347) target legacy per-drawing routes.
  - `handleBulkMove` (1396) posts one `MOVE` to `/api/canvas/bulk`, returns revisions and reconciles optimistic move intents; `handleBulkDelete` begins at 1463. These are shared canvas semantics to reuse/extend, not stamp-only local mutations.
  - `Orthographic2DRenderer` mounts at 1794; it receives `viewSnapshot.assets`, role, membershipId, scene-filtered drawings, tool, and all command callbacks. PLAYER visibility must come from the authorized server snapshot/asset response, not a renderer-side hidden-data filter alone.
- **Renderer interaction + selection:** `apps/web/src/renderers/Orthographic2DRenderer.tsx`
  - Tool/selection state is renderer-local. `handleMapKeyDown` (1355) handles Escape cleanup and switches to PAN; `handlePointerDown` around 1727–1820 starts gestures; `handlePointerUp` (1922) finalizes marquee/freehand; window-level `pointerup`/`pointercancel`/`blur` cleanup is installed around 2022–2050.
  - `movableTargets` (1172) builds revisioned TOKEN/DRAWING targets; marquee selection is committed at 1931–1961; selected-object delete routes through interaction commands around 1540; single drawing move at 3361–3376; group move uses `onBulkMove`.
  - Existing stroke render (3333–3408) assumes every drawing is a `Group` containing `Line(points,color,strokeWidth)`. STAMP must branch rendering to an image/shape while retaining a hit target and canonical selection/move affordance. Do not feed empty stamp points through freehand bbox/marquee calculations.
  - Player drawing interactivity currently requires own author membership plus full fog revelation (967–990 and 3333–3341). Keep “render visible PUBLIC stamp” distinct from “can edit/move it”: render public stamp instances to PLAYER snapshots, while edit commands remain server-authorized. Do not hide the public pixels merely because the PLAYER is not their author.
  - Existing `revealedDrawingIds` derives bounds from freehand points. Stamp bounds must be explicit and size/rotation aware; otherwise reveal/listening/hit geometry is incorrect or can throw on empty points.
- **Renderer contract:** `apps/web/src/renderers/SceneRenderer.ts` has `SceneRendererProps.onDrawingCreate` typed freehand-only (roughly 106–112), and update callbacks only include position/color/strokeWidth. The client should narrow a tagged FREEHAND/STAMP command/DTO union from `@arken/contracts`; avoid widening to loose `Record<string, unknown>` in component contracts.
- **Tool palette / keyboard manifest:** `apps/web/src/renderers/map-tool-shortcuts.ts` owns `MapTool` union and shortcut list; `map-interaction.ts` re-exports the type and enforces GM-only shortcuts in `resolveMapToolShortcut`. `apps/web/src/MapToolbar.tsx` currently renders tool buttons directly (around 220–390), with `data-tool` attributes and GM-specific sections. Add STAMP tool/button and role gating there; palette catalog should not be reachable by PLAYER keyboard shortcut. Add a single shortcut only if product wants one, through the existing manifest (not an ad hoc key handler). `Orthographic2DRenderer.handleMapKeyDown` uses `resolveMapToolShortcut`.
- **History:** `apps/web/src/renderers/CanvasHistoryControls.tsx` fetches role-filtered `/api/canvas/history?sceneId=…`, selects next undo/redo entry, and posts `/api/canvas/undo|redo`. `MapToolbar.tsx` mounts it with `activeCanvasVersion`; `canvas-history-label.ts` fingerprints only canonical per-scene canvas and formats safe labels. Stamp create/move/copy/delete must participate in that same server journal/route; avoid a separate client undo stack or per-object history. Verify mutations trigger canonical snapshot/version refresh, including reconnect and action response/socket ordering.
- **Routes and access (draft):** current draft in `packages/contracts/src/index.ts` defines a tagged strict stamp create command (`kind: STAMP`, allowlisted `assetKey`, `packId`, size/rotation/layer/world x/y) alongside FREEHAND, plus optional stamp fields in update and `DrawingDto`. `apps/server/src/terrain-stamp-routes.ts` registers GM-only `/api/terrain-stamps/catalog` and `/api/terrain-stamps/assets/:assetKey`; asset names are enum/constant-path mapped. PLAYER asset bytes require an active-scene PUBLIC instance; unauthorized is 404 and response is private/no-store. This is intentional: GM palette access does not imply GM-only PUBLIC content. Never put paths or hidden metadata in DTOs, and do not load a GM asset then merely CSS-hide it for players.

On 100/500 instances, renderer should avoid one independent async asset load per object (cache one authorized asset by campaign/key) and avoid a full expensive redraw/reload on each acknowledgement. Reconnect should reload canonical active-scene snapshot/history and not replay local placement or stale preview.

## Compatibility pitfalls / focused acceptance

- The existing freehand API shape assumes nonempty `points`, server create validates at least two x/y pairs, renderer assumes `drawing.points` for bounds, fog reveal and hit geometry, and row/list actions currently only understand drawings by author/revision. Treat stamp bounds and subtype-specific fields as first-class; do not create an invalid hybrid with both stamp and freehand payload.
- A PLAYER may need pixels for an active PUBLIC instance without being allowed the palette, metadata/catalog, GM instance or mutation. Confirm authorization before bytes/cache/range handling; make campaign/active-scene scope part of server checks. Client role filters are not security.
- Single-object `/api/drawings/:id` copy/delete/update and `/api/canvas/bulk` can diverge if their payloads/history omit stamp metadata. Server responses must return complete safe DTOs and preserve subtype through move/copy/undo/redo; disallow client-supplied author/campaign fields.
- Escape currently cancels renderer drafts and changes tool to PAN; `pointercancel` currently flows through outside-stage finish logic (which may finalize an active freehand stroke). For STAMP preview, Escape, pointercancel, blur, tool switch, scene switch, pause, and unmount must clear the uncommitted preview and emit no command. A click commit must run exactly once; avoid duplicate stage and child click placement.
- Reconnect/new snapshot races: existing App create response reconciliation dedupes by ID, whereas stale PATCH recovery refetches after conflicts and bulk moves reconcile queued intents. Stamp mutation acknowledgements must not resurrect deleted/undone objects or overwrite newer revisions after reconnect.

## Suggested bounded frontend browser gate (mocked service; after backend freeze)

GM: palette/catalog appears; asset preview loads; click previews at pointer; rotation/size changes; one click -> exactly one tagged authoritative create request; request contains no client identity; selection/move/bulk move/copy/delete preserve stamp fields and revision; undo/redo shares canvas history; Escape/pointercancel/scene switch cancel draft without write. PLAYER: no catalog/palette and no hidden DTO/asset requests; active PUBLIC instance renders via authorized asset route; GM-only or foreign campaign asset request does not reach image cache; visible public object is not implicitly editable. Include reconnect with canonical snapshot arrival during pending acknowledgement, 100/500 instances (one cached asset per allowed key), and assert no external network dependency. Run desktop + compact viewport; this is mocked browser integration evidence, not live auth, server security acceptance, native-device or production gate.
