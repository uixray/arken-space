# UIX-405 — перемещение токена с клавиатуры и Ctrl-пинг

## Замер

- Ctrl+клик уже ставит пинг в PR #58, но конфликтует с Ctrl-waypoint активной линейки.
- Стрелки уже двигают выбранные объекты через `MapMoveQueue`; WASD отсутствует, а `D` занят инструментом рисования.
- `MapMoveQueue` сериализует и объединяет запросы только пока предыдущий запрос в полёте. При быстрых ответах auto-repeat способен создать поток мутаций.

## Решение

1. WASD получают приоритет только в PAN и только при наличии выбранного управляемого токена; иначе `D` сохраняет существующий shortcut DRAW.
2. Шаг — размер клетки включённой сетки или 8 координат без сетки; Shift умножает шаг на 5.
3. Повторный `keydown` физически удерживаемой клавиши игнорируется. Одно физическое нажатие даёт не более одной мутации и не создаёт сетевой шторм.
4. Поля ввода, composition и комбинации с Alt/Ctrl/Meta не перехватываются.
5. Ctrl, реально добавивший waypoint линейки, подавляет только следующий синтетический Ctrl-click ping; обычный Ctrl+click продолжает ставить пинг.

## Проверка

- Pure tests для раскладки, шага, приоритета `D` и suppression линейки.
- Browser regression для WASD, auto-repeat, DRAW fallback и поля ввода.
- Realtime/browser проверка Ctrl+click ping и отсутствия лишнего ping у линейки, если сценарий надёжно встраивается в существующий multiplayer fixture.
- Обязательная диверсия адресно ломает новую ветку WASD или repeat guard и доказывает падение нового теста.

## Зависимость

Ветка stacked на PR #58 (`codex/uix-621-core-gameplay`), потому что именно там находится пользовательский Ctrl+click ping и актуальный слой массового выбора. Merge и production publication выполняются позже отдельным scope.

## Чекпоинт

- Решение: WASD имеет приоритет только для выбранного управляемого токена в PAN; auto-repeat поглощается, а `D` без такой выборки остаётся shortcut рисования.
- Изменённые файлы: `Orthographic2DRenderer.tsx`, `map-interaction.ts`, `map-interaction.test.ts`, `canvas-token-regressions.spec.ts`, этот план.
- Проверка: pure unit 30/30 PASS; web typecheck и адресный ESLint PASS; UIX-405 browser regression Chromium + Firefox 2/2 PASS.
- Существующее доказательство Ctrl+click: multiplayer GM browser input получает server-authoritative `map:ping` на втором клиенте. Новый pure test закрепляет подавление лишнего ping после Ctrl-waypoint линейки.
- Диверсия: отключение repeat guard дало адресное падение browser regression — ожидалось 5 запросов, получено 10; файл восстановлен.
- Блокеры: отсутствуют для review. Полный связанный CI выполняется в PR; production-сервер не используется.
- Следующее действие: commit, push, stacked PR в PR #58, Linear In Review.

## Продолжение — 2026-09-16, локальный кандидат

Актуальный остаток взят из Linear: keyboard-only ping, touch-механика и
браузерная матрица конфликтов. Старый checkpoint выше описывает прежний
WASD-срез, а не закрытие всей карточки.

В текущем вводе найдены и исправлены три побочных эффекта:

- DOM capture в DRAW теперь не начинает штрих при Ctrl или неосновной кнопке;
- PING не меняет выделение токена, событие остаётся доступным обработчику пинга;
- token drag помнит исходный жест и отменяет Ctrl-перемещение до отправки
  moving/moved/bulk move, в том числе при синхронном dragend из stopDrag.
  Если Ctrl нажат во время drag, локальная позиция возвращается к начальной.

Реестр жестов сохраняется между рендерами. Новый mouse/touch start снимает
старый запрет; resize-события дочерней ручки не становятся перемещением токена.
Приоритет Ctrl-waypoint линейки и серверный путь пинга не менялись. Это не
реализация нового keyboard/touch-пинга и не новая публикация.

Проверено одним адресным пулом: форматирование/ESLint трёх изменённых TS-файлов,
строгие типы helper/test и 46 тестов (16 drag/pointer + 30 map interaction).
Тесты выполняют используемые callbacks, включая синхронную отмену и
Ctrl-click без drag → последующий touch-drag; это не browser/device evidence.

Проверка типов renderer не завершена: изолированный server image не содержит
web-зависимостей, две попытки остановились на разрешении React/Konva/UIkit.
Никакие типы приложения ради проверки не ослаблялись. Browser QA не запускалась
при доступных на ноутбуке примерно 480 МиБ. До приёмки нужны renderer typecheck,
Ctrl-click DRAW/PAN canvas/token, PING selection, Ctrl drag, обычное/group move,
resize, Ctrl-waypoints и touch-регрессии; keyboard-only и touch ping ещё открыты.

## 2026-09-17 — исходный scope и PLAYER/gridless browser gate

Повторно прочитаны живые критерии UIX-405: WASD, шаг на сетке/без неё,
отсутствие перехвата текста, ограничение повторов и общий Ctrl+click ping.
Упоминание keyboard-only ping как обязательного остатка в предыдущем разделе
было расширением исходной задачи. Оно не является новым согласованным требованием;
этот вывод уже зафиксирован в wasd-gate и ctrl-ping-gate. Touch остаётся своим
мобильным этапом, а не поводом незаметно расширять приёмку UIX-405.

В существующий canvas-token-regressions.spec.ts добавлена недостающая матрица:
GM без сетки, PLAYER с сеткой и без неё, PLAYER с выбранным принадлежащим ему
токеном без controller permission, PLAYER с выбранным locked-токеном. Все команды
идут через настоящий App/renderer и реальные клавиатурные события. API/socket
синтетические; серверная авторизация этим не подтверждается.

Положительные случаи проверяют точные MOVE payloads четырёх направлений, шаг64
на сетке и8без неё, Shift×5, одно действие при многократном keydown уже удерживаемой
клавиши и новое действие после keyup. Отрицательные случаи сначала подтверждают
выбранный токен, затем требуют ноль MOVE и других неожиданных записей. Записи
client-logs не исключаются из проверки; отдельно допускается только bootstrap
chat/read bookkeeping. Pageerrors также запрещены.

Первая фикстура ошибочно пыталась выбрать действительно чужой токен: интерфейс
закономерно исключил его из списка объектов. Отрицательный случай исправлен на
owner-without-control, чтобы проверять именно движение уже выбранного, видимого
токена, а не пустой выбор. Правила приложения не менялись и токен не добавлялся
в DOM обходным путём.

Это проверка клиентской маршрутизации команд, не свидетельство физического
перемещения на экране, server persistence или exact-current two-client ping.
Не подменяет прежнюю проверку текста при выбранном токене и отдельный Ctrl+click
пул; их результаты сохранены и не запускались повторно. Старое успешное
multiplayer доказательство относится к релизу7f28ca3, не ко всему новому кандидату.

Итог:10/10PASS в Chrome/Firefox, один worker, retries0,42.0s. В каждом из шести
положительных browser cases —7MOVE; в четырёх отрицательных —0. Неожиданные
записи и pageerrors —0 во всех десяти случаях. Адресные ESLint, E2E typecheck,
Prettier и diffcheck прошли. Полный набор тестов, build и CI не перезапускались.
Артефакты: wasd-role-grid/final-results.json и final-output/ в текущей папке
проверок; первая ошибочная фикстура сохранена отдельно в results.json/output/.

## 2026-09-17 — два настоящих клиента: видимый пинг и клавиатурный перенос

Закрыт конкретный недостаток предыдущих проверок: новый
`tests/e2e/keyboard-ping-live.spec.ts` использует настоящий сервер и два
авторизованных браузерных контекста, без подмены HTTP/socket. GM и PLAYER
поочерёдно перемещают токен клавишей D и ставят Ctrl+click-пинг. Для каждого
браузера создаётся отдельная синтетическая кампания в изолированной базе.

Проверяется не только payload: голубая рамка выбранного токена исчезает со старого
места и появляется на ожидаемом новом месте на обоих canvas; серверный bootstrap
подтверждает ровно один шаг. Девять keydown до keyup дают один MOVE-запрос.
У второго участника семь точек нижней полуокружности пинга становятся золотыми
и затем исчезают. Нижняя полуокружность не пересекается с обычным курсором и
подписью; считываются скомпонованные видимые canvas-слои, а не скрытый React state.
Скриншоты обоих направлений сохранены, Firefox GM→PLAYER визуально просмотрен.

Итог: **4/4 PASS, Chrome и Firefox, 50.258s**, один worker, retries0,
skipped0/flaky0. Pageerrors0, по одному MOVE в каждом сценарии. Использована
неизменённая production web-сборка `1d00a8d`; четыре SHA256 файлов проверены
на диске и через HTTP. API — исходники `ff94551`, PostgreSQL18.1 на loopback.
Это не compiled release API, production, физические устройства или повтор
полного multiplayer CI. Новые данные после перезапуска здесь не проверялись.

Первая попытка остановилась на ошибке тестовой фикстуры: она ожидала GM-only
ручку размера у PLAYER. Проверка заменена на фактические пиксели рамки у обоих,
не на ослабленное отсутствие ошибки. Продуктовый код не менялся. После успешного
прогона добавлены только явные TypeScript-типы frames; E2E typecheck, адресный
ESLint, Prettier и diffcheck проходят.

Сопоставление исходных критериев без расширения scope:

- WASD/шаг/права: прежняя матрица `wasd-role-grid` проверяет четыре направления,
  grid/gridless и запреты; новый реальный gate подтверждает D на сетке,
  авторитетную позицию и отображение у второго участника для GM и PLAYER.
- Текстовые поля: сохранённый `wasd-gate` проверяет настоящий keydown в input,
  textarea/contenteditable при выбранном токене; этот прежний срез не повторялся.
- Удержание: старые клиентские проверки дополнены реальным однократным MOVE
  и подтверждённым шагом в новом gate.
- Ctrl+click виден остальным: теперь подтверждён на текущем runtime у обоих
  участников в обеих ролях, не только старым релизным socket receipt.
