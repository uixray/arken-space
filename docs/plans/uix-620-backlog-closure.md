## Проверка и контрольная точка

Для новых регрессий — адресная проверка и диверсия производственного кода.
Общие гейты на границе связанного пула, а не после каждого метода:
`pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm test`.
Для UI — E2E; для доступа и realtime — multiplayer с Docker.
Код возврата фиксируется непосредственно, без маскирующих конвейеров.

На момент старта зависимости установлены отдельной offline frozen-lockfile
установкой; изменения UIX-448 перенесены без изменения исходного рабочего дерева.
Общие гейты новой ревизии ещё не пройдены. Следующее действие: завершить
контекст подписей, проверить регрессию и интегрировать оставшиеся три ветки.

### Контрольная точка UIX-448

Подписи подключены через отдельный provider вокруг содержимого Sidebar;
формулы в кнопках, каталоге, рабочей области персонажа и карточках ленты
используют словарь кампании. Исходные выражения для отправки не меняются.
Изменены Sidebar, SkillCards, formula-display, RollButton, CatalogEntryPicker,
CharacterWorkspace, два тестовых файла и новый campaign-stat-labels-context.

Адресные тесты: 14/14 PASS. Диверсия: замена значения provider на пустой словарь
вызывает ровно одно ожидаемое падение custom campaign stat label (код 1,
остальные три теста пропущены). После восстановления точных байтов — PASS,
код 0. Первичная сборка зависимостей и приложения завершилась с кодом 0;
это не замена общего гейта интегрированной ревизии.

Блокеров этого среза нет. Следующее действие: коммит UIX-448 и последовательная
интеграция UIX-417, UIX-583, UIX-587; затем общий гейт пула.
