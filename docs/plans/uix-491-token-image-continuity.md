# UIX-491 — непрерывность изображения токена

## Симптом и замер

Два игровых отчёта: назначенное изображение исчезало после движения. Назначение asset уже подтверждается в текущем UI, но нет требуемой сквозной проверки A → B через все пути движения и повторную синхронизацию. Формулировка — симптом, правка допустима только после реального воспроизведения.

## План

1. В существующем изолированном multiplayer GM+6 создать контролируемый токен с различимым asset A.
2. Заменить definition asset на различимый B; подтвердить DTO и видимый canvas у GM/PLAYER.
3. Выполнить настоящий realtime drag мышью, затем `/api/canvas/bulk` MOVE; после каждого проверить B и definitionRevision у обоих.
4. Повторить actionId и отправить конфликтную revision: ни один путь не должен вернуть A.
5. `game:resync` обоим и reload PLAYER: изображение B остаётся.
6. Если текущий код проходит — добавить только regression, не изобретать ложную правку. Если падает — сначала зафиксировать конкретное место потери, затем минимальная правка.

## Проверки

Адресный multiplayer прогон и обязательная диверсия на проверяемом production projection/merge. После task — связанный quality gate, без production. Server владельца выключен и не нужен: Docker полностью изолирован.

## Чекпоинт

- Решение: production уже проецирует изображение из актуального определения токена; исправление кода не требуется. Добавлена сквозная regression-проверка отдельного контролируемого токена.
- Покрытие: замена A → B, видимый canvas GM/PLAYER, историческое расхождение placement=A при definition=B, реальное перетаскивание мышью, bulk MOVE, повтор actionId, конфликт revision, resync и reload.
- Проверка: изолированный `pnpm test:multiplayer` — 2/2 PASS; cleanup и resource leak check — PASS. Production-сервер не использовался.
- Диверсия: временная подмена canonical `latestToken.assetId` на placement asset дала адресное падение UIX-491 после browser drag; production-файл восстановлен байт-в-байт.
- Диагностика: четыре предыдущих падения были ошибками фикстуры (зависимость sharp, неверное ожидание GM media ACL, отсутствие DATABASE_URL у runner, вмешательство в исходный token fixture), а не дефектами продукта.
- Изменённые файлы: `tests/multiplayer/game-session.spec.ts`, `docs/plans/uix-491-token-image-continuity.md`.
- Блокеры: ручная проверка на production откладывается до отдельного publication scope.
- Следующее действие: commit, push, PR и перевод UIX-491 в In Review.
