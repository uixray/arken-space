# UIX-503 — handoff панели карты и подписи истории

## Состояние handoff

- Основа Codex-ветки: `origin/main` `a48de5d`.
- Коммит Claude `1917328` перенесён без изменения ветки `claude/*`.
- PR #50 прошёл GitHub CI, но ревью обнаружило расхождение между обещанной
  подписью Redo и фактическим выбором сервера. Поэтому исходный PR не готов к
  слиянию, несмотря на зелёные гейты.

## Подтверждённый диагноз

1. `GET /api/canvas/history` отдаёт строки по убыванию исходного `sequence`, а
   `POST /api/canvas/undo|redo` выбирает строку по убыванию
   `transitionSequence`. После двух Undo эти порядки расходятся.
2. `activeCanvasVersion` учитывает только количество и максимальную ревизию.
   Изменение объекта с ревизией ниже текущего максимума не вызывает повторную
   загрузку истории, поэтому доступное имя и подсказка могут устареть.
3. Сервер создаёт `CANVAS_BULK_MOVE` и `CANVAS_BULK_DELETE`, но клиент показывает
   для них родовое «действие».
4. Browser-регрессия подтверждает только роль GM. Критерий отсутствия и
   нефокусируемости пустого меню у PLAYER, а также узкая панель, поведением не
   проверены.

## Решения

1. Историю сортирует сервер по тому же `transitionSequence`, который использует
   команда Undo/Redo, и отдельно маркирует `nextDirection` у точного кандидата
   каждого направления. Сам внутренний счётчик наружу не отдаётся. Если после
   ста переходов кандидат выпал из обычной страницы, сервер добавляет его в
   ответ отдельно — кнопка не становится ложно недоступной.
2. Добавить интеграционную регрессию: действия A/B → Undo B → Undo A → GET
   history → POST Redo; объявленная первой UNDONE строка и ответ Redo обязаны
   иметь один `sequence`.
3. Вынести стабильную версию канваса в чистую функцию. Отпечаток включает id и
   revision сцены, каждого токена, рисунка и области тумана, поэтому меняется
   при любой относящейся к истории правке, а не только при новом максимуме.
4. Добавить понятные подписи bulk-переноса и bulk-удаления без имён скрытых
   объектов.
5. Browser-тестом войти PLAYER, поставить узкий viewport и проверить, что
   `toolbar-overflow` отсутствует в DOM и не попадает в клавиатурный обход.
6. Ветку Claude не переписывать. Исправленный результат публикуется из
   `codex/uix-503-history-target-order`; PR #50 после replacement закрывается,
   но не мержится.

## Подзадачи

1. Сначала добавить красные тесты на порядок переходов, отпечаток ревизий и
   bulk-подписи; зафиксировать точные падения до production-правки.
2. Исправить server history order и клиентский отпечаток, не расширяя доступ к
   журналу и снапшоту.
3. Добавить PLAYER/narrow browser-регрессию без подмены роли на клиенте.
4. Провести обязательные диверсии для server order и realtime fingerprint,
   затем вернуть рабочий код.
5. Прогнать явные гейты, создать checkpoint и replacement PR.

## Гейты

```text
pnpm format:check
pnpm lint
pnpm typecheck
pnpm build
pnpm test
pnpm test:e2e
pnpm test:multiplayer
```

`test:multiplayer` обязателен: меняются авторитетный порядок истории канваса и
обновление realtime-подписей. Для Playwright-обёрток проверяется реальный код
возврата без маскирующего конвейера.
