# UIX-470 — инструменты карты

## Замер

Текущий production-код уже содержит заявленное поведение:

- **PASS:** `MapToolbar` показывает короткие текстовые подписи и делит мастерские инструменты на блоки «Туман» и «Метки»; панель можно свернуть до значков.
- **PASS:** `Orthographic2DRenderer` рисует незалитый контур кисти до нажатия, использует тот же `fogBrushRadius`, что и мутация, и убирает контур при уходе курсора или смене инструмента.
- **PASS:** удаление одиночного рисунка выполняется без диалога и остаётся обратимым через журнал действий; подтверждение одиночного токена сохранено.
- **PASS на базе UIX-507:** рамка выбирает доступные игроку рисунки, групповое удаление доведено до мутации и защищено отдельным подтверждением для действительно массового действия.
- **Gap:** эти четыре результата не закреплены полным набором адресных регрессий UIX-470. Задача в этом пуле — закрыть доказательный хвост, а не заново реализовать уже присутствующее поведение.

## Решение

- Не переписывать production-код без воспроизводимого `FAIL` относительно acceptance criteria.
- Считать реализацию UIX-507 базой для выбора и массового удаления; не создавать второй механизм рамки или параллельное состояние выбора.
- Сохранить осознанное различие: одиночный рисунок удаляется сразу и может быть возвращён через undo; групповое удаление нескольких объектов требует подтверждения; токен не приравнивается к рисунку.
- Проверять совпадение предпросмотра кисти и результата через общий радиус/мировые координаты, а не дублировать геометрию в тестовом коде.

## Три тестовых хвоста

1. **Предпросмотр кисти:** адресный контракт мировых координат, общего радиуса preview/persisted brush и очистки на pointer leave/смене инструмента.
2. **Прямое удаление:** server integration доказывает `DELETE drawing → отсутствие в БД → canvas Undo → полное восстановление`.
3. **PLAYER selection:** browser-тест на базе UIX-507 выбирает рамкой два своих видимых рисунка, исключая чужой и свой скрытый туманом, затем отправляет точный bulk DELETE после подтверждения.

## Проверки и диверсии

- Сначала запустить существующие фокусные unit/DOM и UIX-507 browser-сценарии, затем добавить только недостающие ожидания.
- Для каждого нового хвоста выполнить адресную диверсию ожидания. Должен падать соответствующий тест с диагностикой нужного контракта, не весь набор.
- После объединения пула: `pnpm format:check && pnpm lint && pnpm typecheck && pnpm build && pnpm test`.
- Поскольку меняются доказательства UI-потока канваса, запустить соответствующий `pnpm test:e2e`/адресные Playwright-сценарии без конвейера, маскирующего exit code. `test:multiplayer` нужен только если замер выявит изменение realtime/access, которого текущий scope не предполагает.

## Чекпоинт

- **Решения:** production-код не менялся: замер подтвердил реализацию, закрыт только доказательный хвост. UIX-507 остаётся единственным механизмом канонической фильтрации и массового выбора.
- **Ревизия:** будет зафиксирована коммитом после финального scoped gate.
- **Изменённые файлы:** новый `brush-preview.test.ts`, server regression в `tests/pool-b-http.test.ts`, PLAYER browser regression в `tests/e2e/canvas-token-regressions.spec.ts`, этот план.
- **Проверки:** brush unit 2/2 PASS; direct DELETE→Undo 1 PASS (58 skipped); PLAYER Chromium 1/1 PASS; адресные ESLint/Prettier/diff-check PASS.
- **Диверсии:** brush persisted-radius mismatch дал 1 FAIL/1 PASS; неверный restored color изолированно уронил server test; ожидание третьего выбранного рисунка изолированно уронило PLAYER browser test на фактических двух. После каждой диверсии файлы восстановлены, финальные прогоны зелёные.
- **Среда:** первая локальная browser попытка получила Windows `spawn EPERM`; разрешённый повтор прошёл. Production и Docker не использовались.
- **Блокеры:** нет.
- **Следующее действие:** commit, push, stacked PR на UIX-507 и Linear In Review; merge/publication позже общим scope.
