## Actionable P1 findings — repair before acceptance

1. **Old-password login can survive concurrent credential reset/change.** `account-auth-routes.ts`: login reads/verifies account.passwordHash, then creates account session outside a shared transaction/credential version guard. Reset/change updates password and revokes a snapshot of existing sessions. A paused old-password login resumes after that commit and inserts a fresh unrevoked session. Serialize final issuance with credential changes using a common user-row lock and compare the current credential/version to the one verified before inserting. Expensive scrypt may run outside lock; recheck under lock. Reset/change and issuance must use consistent lock order, including action-token issuance; avoid token→user versus user→token deadlocks. Deterministic barrier test: pause after old verifier succeeds, commit reset/change, resume issuance; no surviving account or derived session. Also disabled/unverified change while login waits must fail.

2. **Revoked/expired legacy invite can mutate character ownership even though session issuance fails.** In `routes.ts`, legacy `/api/auth/invite` lookup omits revokedAt. `claimInviteOwnership` creates membership/controllers and changes character owner, then updates invite with only `claimedAt IS NULL`; transaction commits before `createSession` rejects revoked provenance. Expiry is only checked before the transaction, allowing expiry while queued. Claim with conditional non-revoked/unclaimed/unexpired UPDATE inside transaction before ownership mutation; use authoritative DB time after any lock wait. Roll back on any invalid claim. Test already revoked, expires between lookup/claim, revoke/claim race, two claims; loser must leave no new member/controllers or ownership changes, not merely receive non-200.

3. **Mail lifecycle lacks durable atomic issuance/delivery acceptance.** `issueActionToken` commits separately from `sendActionMail`, and account insert is separate again. A send/process failure leaves invalidated previous tokens and an undeliverable current token; retry is not recovery. In-memory sink loses all pending work on restart. This is a public activation blocker, not a statement that local test adapter is invalid. Next pool below closes local durability only; it cannot establish actual email delivery.
