Один связанный browser-сценарий GM/PLAYER: wide → narrow → wide, активный раздел в закрытом «Ещё», keyboard access; переименование из сеанса; измерение после font loading event. Адресная диверсия и один общий gate после связанной реализации. Полные тяжёлые проверки — CI, не повторять локально весь предыдущий пул.

## Чекпоинт готовности

- Решение: название кампании удалено только из верхней панели; GM переименовывает её через меню сеанса. Меню закрывается перед modal, поэтому после Escape фокус возвращается на видимый summary, а не на скрытую кнопку.
- Исправлена подтверждённая причина недостающего места: после удаления имени `.brand` продолжал занимать 467 px при логотипе 78,75 px. Теперь brand занимает содержимое.
- Активный скрытый раздел подписан в стабильном «Ещё» с резервом не более 180 px; полное название остаётся в tooltip. Граница не прыгает при выборе.
- Измерения обновляются после `document.fonts.ready` и `loadingdone` с cleanup.
- Изменено: App.tsx, WorkspaceNav.tsx, styles.css, адресные DOM/E2E и два прежних assertions.
- Проверка: DOM/unit 4/4 PASS; integrated Chrome+Firefox 16/16 PASS; web typecheck/build PASS; изменённые файлы lint 0 errors (две прежние warnings App). Диверсии baseline/active/fonts дали адресные FAIL и восстановлены.
- Блокеры: production не нужен. Следующий шаг — локальный коммит, stacked PR после CI базового PR58. Merge/deploy не выполнять.
