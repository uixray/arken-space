## Проверка

- Оркестратор воспроизвёл старый HUD новым Chromium GM desktop тестом: при выборе одного токена x блока масштаба изменился с `843.78125` до `600.9375`, то есть на `242.84375` CSS px. FAIL получен на реальных границах элемента, а не поиске строки исходника.
- Новые сценарии сравнивают x/y/width/height в одном viewport с `toBeCloseTo(..., 1)` — разница строго менее `0.05` CSS px. Проверяются 0/1/несколько токенов и рисунков, смешанная группа, Escape и пустой клик.
- Положительное доказательство выбора: `aria-pressed` настоящего списка объектов, панель рисунка и подтверждение группового удаления с количеством/типами. Отмена не отправляет мутацию и сохраняет группу; после очистки Delete не действует.
- Масштаб проверяется реальными +/− и клавишей End на нативном range; сверяются value и видимый процент. «Вписать» возвращает исходную камеру фикстуры перед жестами.
- Сохранены содержимое GM-запросов MOVE/DELETE для смешанной группы и ограничения PLAYER: исключение недоступных объектов, разрешённые цели DELETE и очистка после отзыва доступа.
- Смешанная группа сохраняется в PNG каждого viewport/роли для визуального просмотра оркестратором. Синтетические API-фикстуры не являются доказательствами production/multiplayer.
- Статическая проверка исполнителя: адресный Prettier, web/E2E TypeScript, адресный ESLint и `git diff --check` PASS. Первый web TypeScript выявил три неподдерживаемые опции RTL `exact`; исправлены до финального PASS.
- Финальная браузерная и DOM-проверка с настоящим Gravity пока ожидают интеграции оркестратора. Результат старого базового SHA не переносится на новую ревизию автоматически.

## Продолжение после проверки оркестратора и независимого ревью

- База корректировки: `ddfeb0461290ee771c98d3521eb13c5756b72a31`; изменены только `styles.css`, E2E-файл и эта контрольная точка.
- Проверка оркестратора на интеграционном кандидате выявила FAIL четырёх новых сценариев геометрии: после первого Escape оставалась одна активная строка. Причина в тестовом помощнике, не в production Escape: выбор строки не закрывает список, а повторный клик элемента открытия выполняет закрытие нажатием снаружи, затем снова `open-object-list`. Следующий Escape правильно закрывал лишь список и сохранял выделение.
- Помощники теперь открывают список из явно закрытого состояния и закрывают его клавишей Escape с ожиданием `aria-expanded=false` и скрытого popover. Только отдельный Escape на canvas проверяет очистку выделения. Обработчики продукта не менялись.
- Независимое ревью подтвердило P2: групповое действие с `z-index:26` перекрывало первую строку списка (`z-index:25`). Слой действия понижен до 24, без повышения popover или изменения его положения.
- В каждом сценарии геометрии живая смешанная группа открывает список; первый Escape закрывает только список, а повторное подтверждение доказывает сохранение четырёх объектов. Затем тест открывает список снова, находит реальное пересечение первой строки и группового действия, проверяет `elementFromPoint` и нажимает в этих пикселях обычным кликом без `force`. Требуется реальный выбор токена, исчезновение групповой кнопки и отсутствие диалога/запроса удаления.
- Статическая проверка корректировки: адресный Prettier, web/E2E TypeScript, ESLint E2E-файла и `git diff --check` — PASS.
- Итоговая браузерная проверка этой корректировки ещё не выполнена; её запускает оркестратор после интеграции. Исполнитель не запускал браузер/полный CI и не выполнял записи Git/Linear.
