## G. Подтверждённые структурные риски и открытые вопросы выполнения

1. **Несколько overlay-систем:** уровни владельцев FormSelect; нативные details; Gravity Popup; локальные меню стикеров/slash-команд/контекста; портал персонажа в body; системные элементы управления. Повышение одного z-index не создаёт общий контракт для остальных.
2. **Контекст наложения важнее голого z:** topbar1000 содержит account40 и nav popup1000; toolbar24 содержит grid32; viewport `overflow:hidden` обрезает дочерние элементы независимо от их больших чисел. Центрирование workspace по умолчанию через `transform` тоже образует контекст. Нужны вычисленная цепочка предков + hit-test, а не сравнение двух CSS-литералов.
3. **Хук владельца применяется не ко всему:** CursorPresence Popup и Select предпросмотра без общей обёртки не используют его; элементы управления листа персонажа в потоке получают B, а не W. Последнее соответствует текущей z900 поверхности, не объявлено дефектом.
4. **Глубина вложенности не моделируется:** тип владельца — три строки, без ID родителя/экземпляра/стека. Modal popup2001 потенциально выше другого modal2000. UIX-502 уже записывает отсутствие доказательства произвольных одновременно открытых вложенных модальных окон. Никакая новая архитектурная правка этим документом не разрешена.
5. **Механизм закрытия не арбитр верхнего слоя:** каждый details подписан на document Escape, контекстное меню — на window Escape, StickerPicker имеет свой обработчик. Структурный E3 не доказывает «один Escape — один владелец» при совместном открытии. Это вопрос выполнения, не утверждение о воспроизведённом дефекте.
6. **Скрытый/сохраняемый владелец:** портал Select находится вне DOM скрытого владельца; нужно проверить закрытие/недоступность при переключении workspace/вкладки/компактного режима. `hidden/inert` на родителе само по себе не является доказательством для портала в document. Не активировать устаревшие скрытые элементы управления ради теста.
7. **Проверка обнаружения неполна по конструкции:** UIX-531 покрывает фиксированные 9 файлов и только details; новые собственные/Gravity popup туда автоматически не попадут. Статический реестр выше дополняет, но не заменяет приёмку во время выполнения.
8. **Пробелы покрытия:** для значительной части строк отсутствуют адресные проверки границ экрана/прокрутки/масштабирования/visualViewport/hit-test/возврата фокуса в каждом месте использования и переходов вложенных владельцев. Все они остаются **BLOCKED — ещё не выполнено**, а не PASS по общему тесту обёртки.

## I. Предлагаемый общий контракт и один следующий связанный пул

Предложение для согласования, не утверждённая реализация и не требование переписать все механизмы. Отдельный канонический `docs/overlay-contract.md` принадлежит оркестратору, этот реестр его не заменяет:

- Каждый overlay знает триггер, поверхность-владельца, родительский overlay (если есть), вид (`menu/listbox/dialog/inline/OS`), доступность роли и собственного владельца прокрутки. Элементы в потоке/OS явно исключаются из менеджера слоёв DOM popup.
- DOM popup видим и доступен для hit-test внутри visual viewport у границ экрана, при масштабировании, прокрутке и клавиатуре компактного режима; допустимы flip/shift/ограниченная внутренняя прокрутка. Обрезание владельцем устраняется локальным порталом/размещением, не глобальным `overflow:visible` или повышением всех меню над модальными окнами.
- Popup выше **своего** владельца и ниже чужого блокирующего модального окна; только верхний подходящий overlay получает Escape. Клик снаружи закрывает без кражи фокуса у новой цели; Escape/выбор возвращают фокус на доступный подключённый триггер по явной политике.
- Закрытие/скрытие/размонтирование/потеря роли владельца закрывает или делает inert дочерний popup; портал в body не остаётся после него интерактивным сиротским элементом. Для вложенного перехода заранее определяется замена или стек; не смешивать эти случаи в доказательствах.
- Семантика соответствует модели взаимодействия: button/menuitem против combobox/listbox/option; доступное имя/expanded/controls, клавиатурная навигация, причина disabled и связь с ошибкой проверяются на реальном элементе управления, не только в свойствах обёртки.

**Один пул выполнения после изменений scene-picker и фиксации ревизии:** воспроизведённый крайний случай scene-picker верхней панели + уже существующий пул popup UIX-502 normal/cap/modal + закрытие nav/account/music/details + один собственный popup чата + одно меню холста + переключение владельца GM/PLAYER в компактном режиме. Chromium/Firefox, retries=0, безопасные синтетические фикстуры. Для каждого результата: точная ревизия/viewport/роль, снимок экрана, вычисленные цепочка владельцев/z/overflow/transform и `elementFromPoint`, результат действия/клавиатуры/закрытия/фокуса; адресная диверсия для новой регрессионной проверки. Не запускался этим исполнителем.

**Следующее действие:** оркестратор интегрирует своё минимальное исправление scene-picker, определяет репрезентативные случаи выполнения из этого реестра и записывает отдельный протокол проверки. До этого ни общее утверждение «все меню работают», ни новая готовность production из статического реестра не следуют.
