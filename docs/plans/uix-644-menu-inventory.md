## G. Подтверждённые структурные риски и открытые runtime-вопросы

1. **Несколько overlay-систем:** FormSelect owner tiers; native details; Gravity Popup; local sticker/slash/context menus; body character portal; OS controls. Повышение одного z-index не создаёт общий контракт для остальных.
2. **Stacking context важнее голого z:** topbar1000 содержит account40 и nav popup1000; toolbar24 содержит grid32; viewport `overflow:hidden` обрезает descendants независимо от их больших чисел. Default centered workspace `transform` тоже образует context. Нужны computed ancestor chain + hit-test, а не сравнение двух CSS literals.
3. **Owner hook применяется не ко всему:** CursorPresence Popup и preview raw Select не используют его; character sheet inline controls получают B, а не W. Последнее соответствует текущей z900 поверхности, не объявлено дефектом.
4. **Nested depth не моделируется:** тип owner — три строки, без parent/instance/stack ID. Modal popup2001 потенциально выше другого modal2000. UIX-502 уже записывает отсутствие доказательства arbitrary simultaneous nested modal. Никакая новая архитектурная правка этим документом не разрешена.
5. **Dismissal не арбитр верхнего слоя:** каждый details подписан на document Escape, context menu — на window Escape, StickerPicker имеет свой handler. Structural E3 не доказывает one-Escape/one-owner при совместном открытии. Это runtime-вопрос, не утверждение о воспроизведённом дефекте.
6. **Hidden/retained owner:** Select portal находится вне скрытого owner DOM; нужно проверить закрытие/недоступность при workspace/tab/compact switch. `hidden/inert` на parent само по себе не является доказательством для document portal. Не активировать legacy hidden controls ради теста.
7. **Discovery guard неполон по конструкции:** UIX-531 покрывает фиксированные 9 файлов и только details; новые custom/Gravity popup туда автоматически не попадут. Статический реестр выше дополняет, но не заменяет runtime acceptance.
8. **Coverage gaps:** consumer-specific screen-edge/scroll/zoom/visualViewport/hit-test/focus restore и nested-owner transitions отсутствуют для значительной части строк. Все они остаются **BLOCKED — not yet executed**, а не PASS по общему wrapper тесту.

## I. Предлагаемый общий контракт и один следующий связанный pool

Предложение для согласования, не утверждённая реализация и не требование переписать все механизмы. Отдельный canonical `docs/overlay-contract.md` принадлежит оркестратору, этот inventory его не заменяет:

- Каждый overlay знает trigger, owner surface, parent overlay (если есть), kind (`menu/listbox/dialog/inline/OS`), доступность роли и собственный scroll owner. Inline/OS исключаются из DOM popup layer manager явно.
- DOM popup видим и hit-testable внутри visual viewport при screen-edge, zoom, scroll и compact keyboard; допустимы flip/shift/ограниченный внутренний scroll. Owner clipping устраняется scoped portal/placement, не глобальным `overflow:visible` или повышением всех меню над modal.
- Popup выше **своего** owner и ниже чужого blocking modal; только topmost eligible overlay получает Escape. Outside click закрывает без кражи фокуса у нового target; Escape/selection возвращают focus на доступный connected trigger по явной политике.
- Закрытие/скрытие/unmount/role loss owner закрывает или делает inert дочерний popup; body portal не переживает его как интерактивный orphan. Nested transition заранее определяет replace или stack; не смешивать эти случаи в evidence.
- Семантика соответствует interaction model: button/menuitem против combobox/listbox/option; accessible name/expanded/controls, keyboard navigation, disabled reason и error linkage проверяются на реальном контроле, не только wrapper props.
