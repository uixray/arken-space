## 2026-09-12 — Escape во внешнем окне «Токены»

- На опубликованном интерфейсе дважды воспроизведено: Escape в раскрытом списке изображения токена закрывает и список, и всё рабочее окно. Выбор/сохранение/загрузка не выполнялись. Это внешний `TokenPalette` → `FormSelect` в workspace, не grid AssetPicker в модальном редакторе. Точная опубликованная ревизия не установлена.
- Причина подтверждена также в текущей базе M77: workspace-ветка `ArkenDialog` безусловно закрывает окно на bubbling Escape. Прежние browser-сценарии модального редактора этого владельца не покрывают.
- Локальная правка учитывает уже обработанное событие, DOM-владельца (включая вложенный dialog и React portal) и раскрытый combobox. Первый Escape оставлен дочернему Select; закрытое поле не блокирует следующий Escape окна. Ветка modal, слои, данные и действия назначения не менялись.
- Подготовлены четыре DOM-сценария: настоящий Gravity FormSelect с двумя Escape, consumed event, React portal, вложенное рабочее окно. Новый browser spec `workspace-select-escape.spec.ts`: настоящий App/TokenPalette, GM/PLAYER × 1280/390, синтетические API, hit-test списка, неизменность выбранного изображения, возврат фокуса, два Escape и отсутствие игровых мутаций.
- **Проверено только исходное поведение опубликованного интерфейса и исходный код. Исправленная ревизия ещё не запускалась:** DOM/browser/formatter/types/lint остаются отдельным hosted gate. Синтетический API не доказывает серверные права; это не закрытие всего UIX-644/UIX-502. Публикации и deploy нет.

## G. Подтверждённые структурные риски и открытые вопросы выполнения

1. **Несколько overlay-систем:** уровни владельцев FormSelect; нативные details; Gravity Popup; локальные меню стикеров/slash-команд/контекста; портал персонажа в body; системные элементы управления. Повышение одного z-index не создаёт общий контракт для остальных.
2. **Контекст наложения важнее голого z:** topbar1000 содержит account40 и nav popup1000; toolbar24 содержит grid32; viewport `overflow:hidden` обрезает дочерние элементы независимо от их больших чисел. Центрирование workspace по умолчанию через `transform` тоже образует контекст. Нужны вычисленная цепочка предков + hit-test, а не сравнение двух CSS-литералов.
3. **Хук владельца применяется не ко всему:** CursorPresence Popup и Select предпросмотра без общей обёртки не используют его; элементы управления листа персонажа в потоке получают B, а не W. Последнее соответствует текущей z900 поверхности, не объявлено дефектом.
4. **Глубина вложенности не моделируется:** тип владельца — три строки, без ID родителя/экземпляра/стека. Modal popup2001 потенциально выше другого modal2000. UIX-502 уже записывает отсутствие доказательства произвольных одновременно открытых вложенных модальных окон. Никакая новая архитектурная правка этим документом не разрешена.
5. **Механизм закрытия не арбитр верхнего слоя:** каждый details подписан на document Escape, контекстное меню — на window Escape, StickerPicker имеет свой обработчик. Структурный E3 не доказывает «один Escape — один владелец» при совместном открытии. Это вопрос выполнения, не утверждение о воспроизведённом дефекте.
