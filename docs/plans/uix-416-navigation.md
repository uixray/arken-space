# Навигация в верхней панели с переполнением в «Ещё» — план работ (UIX-416)

Исходная ревизия `b27acde`. Статус на `42c7ccc`: новая `WorkspaceNav`
зафиксирована в `2b22ff7` в составе UIX-472; документ сохранён как исходное
UX-обоснование, а не как текущий task tracker.

Находка 3a из [UX-разбора](../ux-review-2026-08-10.md). Смежные, но **отдельные**
задачи: UIX-417 (непереведённые пункты) и UIX-423 (два одинаковых названия
энциклопедий). Здесь они не решаются — но план сводит подписи в одно место,
чтобы обе стали правкой строк в массиве.

### 1.2 Что уже сделано руками и почему это надо заменить

Топбар адаптируется лестницей из четырёх брейкпоинтов, каждый прячет ещё одну
надпись:

| Ширина   | Что прячется                                          | Где                    |
| -------- | ----------------------------------------------------- | ---------------------- |
| ≤ 1500px | статусные подписи, «сейчас играет» сжимается до 120px | `styles.css:2407-2414` |
| ≤ 1180px | слово «Рабочее пространство», заголовок «Музыка»      | `styles.css:3732-3746` |
| ≤ 1150px | название кампании                                     | `styles.css:2401-2404` |

Это ровно тот подход, который задача просит заменить: пороги подобраны под
конкретные подписи и разъедутся, как только UIX-417 переведёт «World maps» в

Попутная находка: правило `.topbar { grid-template-columns: ... }` в
`styles.css:2398-2400` — мёртвое. `.topbar` объявлен `display: flex`
(`styles.css:206-215`), у flex-контейнера этого свойства нет. Удалить отдельным
коммитом, чтобы не мешалось в диффе.

### 1.3 Нижняя граница ширины

`body { min-width: var(--app-min-width) }` = **960px** (`styles.css:51`,
`116-118`). Уже этого окно не сжимается — появляется горизонтальная прокрутка
всей страницы. Это существенно для §7: «вообще ничего не влезает» — не
гипотетический телефон, а вполне реальный набор «960-1100px, мастер, длинное
название сцены, играет музыка».

## 3. Решение отдельно от вёрстки

В проекте это устоявшийся приём: `renderers/fog.ts` (`fogHiddenTokenIds`),
`renderers/camera-fit.ts` (`fitRect`), `ui/asset-picker-logic.ts`,
`ui/dismissible-details.ts` (`shouldDismissDetails`). Комментарий над
`fogHiddenTokenIds` формулирует, зачем: чтобы тестировалось **решение**, а не
только арифметика под ним.

Здесь решение — одна функция:

**`apps/web/src/ui/overflow-nav.ts`**

```
overflowNavLayout({
  available,                       // ширина контейнера, px
  itemWidths,                      // ширины всех пунктов по порядку
  moreWidths: { full, compact },   // «Ещё» текстом и иконкой
  gap,
}) -> { visibleCount, moreVariant: "none" | "full" | "compact" }
```

Правила, каждое — отдельный тест:

1. Если сумма всех пунктов с промежутками помещается — `visibleCount` = все,
   `moreVariant: "none"`. Пустого меню-приманки не бывает.
2. Иначе резервируется место под «Ещё» и набирается **префикс** списка, пока
   помещается.
3. Если с текстовым «Ещё» не помещается ни один пункт, а с иконочным помещается
   хотя бы один — берётся иконочный. Это и есть замена медиазапросу «на узком
   показывать `⋯`».
4. Если не помещается ничего ни в одном варианте — `visibleCount: 0`,
   `moreVariant: "compact"`. «Ещё» рендерится всегда: терять единственную точку
   входа в навигацию нельзя ни при какой ширине.
5. `available <= 0` (первый кадр, до layout) → `visibleCount: 0`. Деградация в
   сторону сегодняшнего поведения, а не в сторону расползшейся панели.

**Почему именно префикс, а не «упаковать как можно больше».** Порядок фиксирован
требованием, значит видимые — всегда начало списка. Жадная упаковка («узкий
пункт №7 влез бы вместо широкого №4») дала бы дыры в порядке — ровно то, из-за
чего кнопки перестают запоминаться. Отказ от неё убирает целый класс дефектов и
делает функцию тривиально проверяемой.

**Состав пунктов — тоже данные, а не JSX.** Сейчас это девять кусков разметки с
условиями по роли. Вынести в `apps/web/src/ui/workspace-nav-items.ts`:

```
workspaceNavItems({ role, operatorFeedbackAllowed })
  -> readonly { id: WorkspaceDestination; label: string }[]
```

Тест — состав и порядок для GM и PLAYER, влияние `operatorFeedbackAllowed`,
зависимость подписи заявок от роли. Это же место, где потом дёшево делаются
UIX-417 и UIX-423.

## 4. Механика измерения

Меряются два разных числа из двух разных источников, и путать их нельзя.

### 4.1 Ширины пунктов — через постоянное «зеркало»

Ширину пункта, которого нет в DOM, измерить нельзя. Если мерить сами кнопки
панели, то после переноса в «Ещё» их ширины теряются — и при расширении окна
нечем решить, влезет ли пункт обратно. Это классическая ошибка этого виджета: он
сжимается и не разжимается.

Решение — постоянно смонтированный зеркальный ряд со **всеми** пунктами:

- `position: absolute; visibility: hidden; pointer-events: none; white-space: nowrap`;
- `aria-hidden="true"` + `inert` + `tabIndex={-1}` на кнопках — иначе получим по
  два элемента «Персонажи» в дереве доступности и вторую копию в порядке
  табуляции;
- та же типографика и те же отступы, что у настоящих кнопок (один CSS-класс на
  оба ряда).

Абсолютное позиционирование выводит зеркало из потока — оно **физически не
может** повлиять на ширину контейнера. Это первый и главный замок против цикла.

Мерить `getBoundingClientRect().width`, а не `offsetWidth`: второй округляет до
целых, и на дробном зуме (110%, 125%) накопленная ошибка в 1px даёт то самое
«через раз мигает».

Отвергнутая альтернатива: отрисовать всё, померить, свернуть. Даёт видимую
вспышку на первом кадре и не отвечает на вопрос «влезет ли обратно».

### 4.2 Доступная ширина — `ResizeObserver` на одном узле

Наблюдается ровно один элемент: контейнер навигации. Он обязан быть
`flex: 1 1 auto; min-width: 0`, то есть его ширина задаётся раскладкой топбара, а
не содержимым. Это второй замок: сколько бы пунктов мы ни показали, наблюдаемая
ширина не изменится.

В колбэке читается
`entry.contentBoxSize?.[0]?.inlineSize ?? entry.contentRect.width`. Внутри
колбэка **не вызывается** `getBoundingClientRect()` по другим узлам — это
принудительный синхронный layout прямо в фазе доставки уведомлений, главный
источник срыва цикла.

Почему `ResizeObserver`, а не `window.resize`: доступная ширина меняется без
изменения окна. `.scene-switcher` — `flex: 0 0 auto` и содержит **название сцены
текстом** (`App.tsx:1413`); переключили сцену с «Тракт» на «Заброшенная шахта у
Северного перевала» — навигация стала уже. То же с названием трека в музыкальной
панели и с появлением/исчезновением кнопок «показать сцену»/«создать сцену»
(`App.tsx:1466-1517`, зависят от наличия активной сцены).

### 4.3 Когда мерить

| Повод                                  | Механизм                                             |
| -------------------------------------- | ---------------------------------------------------- |
| Монтирование                           | `useLayoutEffect` — расчёт до кадра, чтобы не мигало |
| Изменение доступной ширины             | `ResizeObserver` на контейнере                       |
| Изменение состава или подписей пунктов | Зависимость эффекта — ключ из `id` и подписей        |
| Загрузка шрифта                        | `document.fonts?.ready` + событие `loadingdone`      |

**Про шрифт — честно.** Топбар рисуется системным стеком:
`--font-sans: system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`
(`styles.css:6-7`), а `button { font: inherit }` (`styles.css:119-125`)
распространяет его на кнопки меню. Inter подтягивается Gravity UI
(`@gravity-ui/uikit/styles/fonts.css` — это один `@import` с Google Fonts,
`display=swap`) и применяется только к компонентам Gravity через
`--g-font-family-sans`. То есть **если пункты навигации сделать нативными
`<button>`, как сейчас в `.workspace-menu__content`, веб-шрифт на их ширину не
влияет и точка переполнения не прыгнет.**

Это не повод не подстраховаться: подписка на `document.fonts.ready` — три строки,
и она закрывает случай, когда кто-то позже переведёт пункты на Gravity `Button`
(в проекте это происходит регулярно — см. `Sidebar.tsx`, `SetupPanel.tsx`).
Обязательно через optional chaining: **jsdom 30.0.1 не реализует
`document.fonts`** — проверено, `FontFaceSet` не упоминается ни в
`living/interfaces.js`, ни в `nodes/Document-impl.js`. Обращение без guard уронит
component-тест.

### 4.4 Четыре замка против цикла «померили → переставили → померили»

| Замок                                                         | Что держит                                             |
| ------------------------------------------------------------- | ------------------------------------------------------ |
| Зеркало вне потока                                            | Смена состава видимых не меняет ширину контейнера      |
| Контейнер сайзится родителем (`flex: 1 1 auto; min-width: 0`) | То же, со стороны раскладки                            |
| `setState` только при изменении решения                       | Уведомление о той же ширине ничего не делает           |
| Никакого чтения layout других узлов в колбэке                 | Нет принудительного layout внутри доставки уведомлений |

Плюс сравнение ширин с эпсилоном (0.5px) против дребезга на дробных ширинах.

**Почему это важнее, чем кажется.** `installGlobalErrorReporting`
(`error-reporting.ts:21-38`) отправляет на сервер **любой** `window.error`, а
браузер сообщает о срыве цикла ResizeObserver именно как `ErrorEvent` с
сообщением «ResizeObserver loop completed with undelivered notifications».
Небрежная реализация не просто мигает — она заливает ingest ошибок и рабочее
пространство «Operator feedback» шумом с каждого стола, у которого кто-то потянул
границу окна. Чистая консоль после пяти минут ресайза должна стоять в критериях
приёмки.

## 5. Доступность

- **Пункты панели — обычные `<button>`**, каждая в порядке табуляции.
- **Ничего не клипить через `overflow: hidden`.** Клипнутая кнопка остаётся
  фокусируемой: Tab уедет в невидимое и прокрутит контейнер. Переполнившиеся
  пункты не рендерятся в панели вовсе — они существуют только в меню «Ещё».
- **«Ещё» — `<details>/<summary>`**, как `.account-menu`, `.music-overflow`,
  `.toolbar-overflow`. Подключить `useDismissibleDetails`
  (`ui/dismissible-details.ts`): закрытие по Escape с возвратом фокуса на
  `summary` и по клику снаружи там уже реализовано и покрыто тестом.
- **Ролей `menu`/`menuitem` не вводим.** Они обязывают к полной клавиатурной
  семантике меню (стрелки, Home/End, typeahead), которой в проекте нигде нет.
  Кнопки внутри `<details>` — сложившийся здесь приём.
- `<nav aria-label="Рабочие пространства">` вокруг панели: `nav` с `aria-label`
  уже используется в `Sidebar.tsx:296`, `SetupPanel.tsx:72`,
  `CharacterWorkspace.tsx:164`.
- **Активное пространство** — `aria-current="true"` на кнопке. Приём уже есть:
  `WorldMapsWorkspace.tsx:518`, стиль `[aria-current="true"]` в
  `styles.css:2974`.
- **Активное, но переполнившееся.** `<summary>` кнопки «Ещё» получает
  `aria-current="true"`, визуальный маркер и подпись, называющую активное
  пространство: «Ещё: Файлы» (в компактном варианте — только маркер плюс
  `aria-label`).

  > Отвергнутая альтернатива — «подтягивать» активный пункт в панель. Порядок он
  > бы сохранил, но состав видимых менялся бы при каждом переключении, то есть
  > кнопки снова начали бы ездить. Это ровно то, против чего написано требование
  > о фиксированном порядке.

- **Возврат фокуса при закрытии пространства.** Сейчас
  `handleWorkspaceChange(null)` возвращает фокус на `.workspace-menu summary`
  (`App.tsx:444-448`), и на это опирается e2e (`concept.spec.ts:1536`). После
  изменения фокус должен возвращаться на **тот элемент, из которого пространство
  открыли**: на кнопку в панели, если пункт виден, иначе на `summary` «Ещё».
  Хранить id последнего триггера; если за время работы пространства окно сузили и
  пункт уехал в «Ещё» — фокус идёт на «Ещё». Иначе фокус уйдёт в никуда, и это
  тихая регрессия, которую тест обязан ловить.

## 6. Что показывать вместо названия кампании

**Короткий ответ: ничего.** Но одну вещь надо перенести, иначе задача тихо удалит
функцию.

`.campaign-name-button` (`App.tsx:1373-1383`) — **единственная точка входа в
переименование кампании во всём приложении.** Проверено:
`setCampaignRenameOpen(true)` вызывается ровно из одного места. Убрать её вместе с
названием — значит убрать переименование.

Предложение:

- Слово `arken-space` (`.brand strong`) оставить как якорь «где я»: оно узкое и
  на ≤1020px уже прячется существующим правилом.
- Название кампании из панели убрать: оно не несёт работы (кампания одна) и
  занимает `flex: 1 1 220px`.
- Пункт «Переименовать кампанию» перенести в меню сеанса
  (`.account-menu__content`, `App.tsx:1607-1669`), где уже живут «Сменить
  игрока», «Выйти» и сведения о сборке. Условие показа — то же, что сейчас:
  мастер и не режим предпросмотра. `TextPromptDialog` (`App.tsx:1694-1715`)
  переиспользуется как есть.
- Освободившееся место отдаётся навигации: растягивающимся элементом топбара
  становится контейнер навигации, а не `.brand`.

Альтернатива — вкладка «Обзор» в «Подготовке» (`SetupPanel.tsx:64-105`), где уже
переименовывают игроков. По смыслу логичнее, но дороже: там надо заводить блок и
форму. Меню сеанса — одна кнопка и готовый диалог. Решение за владельцем задачи
(см. §11).

**Чего не показывать.** Имя игрока, роль и статус связи уже есть в меню сеанса.
Продублировать их в освободившемся месте — вернуть ту же проблему, из-за которой
задача заведена.

## 7. Очень узкое окно

Ширина топбара не опускается ниже 960px (§1.3). Поведение по убыванию:

| Состояние                                  | Что видно                                                  |
| ------------------------------------------ | ---------------------------------------------------------- |
| Влезает всё                                | Все пункты, «Ещё» не показывается                          |
| Влезает часть                              | Префикс списка + «Ещё» текстом                             |
| Не влезает ни один пункт с текстовым «Ещё» | Иконочное «Ещё» `⋯`; если так влезает пункт — показать его |
| Не влезает ничего                          | Только «Ещё» со всем содержимым                            |
| Не влезает даже «Ещё»                      | «Ещё» всё равно рендерится, `flex: 0 0 auto`               |

Последняя строка — сознательное решение: формально это уже переполнение
раскладки, но лучше пусть «Ещё» подвинет соседа, чем навигация исчезнет целиком.
Контейнер получает `min-width: 0` и `overflow: visible`, чтобы кнопка не была
обрезана.

Заметьте, что **худший случай не хуже сегодняшнего**: сегодня все девять пунктов
и так лежат за одной кнопкой.

Ниже 960px (телефон; в `concept.spec.ts:725-728` есть тест на 390×844) страница
целиком уезжает в горизонтальную прокрутку — существующее поведение приложения,
эта задача его не меняет. Отдельная мобильная раскладка — не здесь.

## 9. Что тестом, что руками

**Юнит (vitest, node) — `overflow-nav.test.ts`:** влезает всё; влезает часть; не
влезает ни одного; выбор компактного «Ещё»; не влезает даже «Ещё»; пустой список;
`available = 0`; дробные ширины и эпсилон; видимые — всегда префикс (свойство
фиксированного порядка).

**Юнит (vitest, node) — `workspace-nav-items.test.ts`:** состав и порядок для GM
(9) и PLAYER (6); `operatorFeedbackAllowed` добавляет пункт обеим ролям; подпись
заявок зависит от роли. Проверять по `id`, а не по подписям, кроме одного явного
теста подписей — иначе UIX-417 и UIX-423 покрасят половину набора.

**Component (vitest, jsdom) — по образцу `ui/useFollowScroll.dom.test.tsx`:**

- при заданных ширинах в панели ровно N кнопок, остальные — в «Ещё»;
- переполнившийся пункт открывает то же пространство, что и раньше;
- Tab доходит до «Ещё», Enter открывает, Escape закрывает и возвращает фокус на
  `summary`;
- активное пространство помечено `aria-current`; когда оно в «Ещё» — помечен
  `summary`;
- после закрытия пространства фокус возвращается на исходный триггер;
- зеркало не даёт второго элемента с тем же доступным именем.

Тестовая оснастка, которую придётся дописать:

- **Ширины.** В jsdom нет layout, `getBoundingClientRect()` возвращает нули.
  Подменять на узлах/прототипе — так уже сделано для `scrollTop`/`scrollHeight` в
  `useFollowScroll.dom.test.tsx:19-40`.
- **`ResizeObserver`.** В `test-support/dom-mocks.ts:45` уже есть
  `installResizeObserverMock()`, но он no-op, а тесту нужно **вызывать** колбэк с
  заданной шириной. Добавить туда же управляемый вариант — по прямому указанию в
  док-комментарии самого файла («добавьте установщик здесь, а не одноразовый мок
  в файле теста»).
- **`document.fonts`.** В jsdom отсутствует (проверено). Guard в коде обязателен
  независимо от тестов; установщик в `dom-mocks.ts` — по необходимости.

**E2E (Playwright):** на 1920 в панели видно N пунктов и «Ещё»; на 1024 видно
меньше; после сужения окна пункт уехал в «Ещё» и по-прежнему открывается;
названия кампании в панели нет; переименование доступно из меню сеанса.

**Руками (browser QA):**

- нет вспышки «все пункты → свернулись» на первом кадре и при перезагрузке;
- нет дребезга при медленном перетаскивании границы окна;
- **консоль чистая: ни одного «ResizeObserver loop»**; после пяти минут ресайза в
  ingest ошибок не появилось новых `window.error`;
- зум 125% и 150%, увеличенный системный размер шрифта;
- длинная (~40 символов) сцена в переключателе — навигация сжимается, а не ломает
  строку;
- у мастера и у игрока; в режиме предпросмотра «глазами игрока»;
- клавиатурой, без мыши, до каждого из 9 пунктов.

## 11. Открытые вопросы

1. **Какой именно порядок фиксируем?** Требование — фиксированный, но текущий
   порядок в коде (персонажи, токены, сцены, подготовка, энциклопедия мира, world
   maps, энциклопедия, заявки, operator feedback, файлы) частоте не соответствует.
   Порядок выбирается один раз и больше не меняется — значит выбрать его надо
   осознанно, а не унаследовать. Предложение: персонажи, сцены, токены, заявки,
   подготовка, карты мира, энциклопедии, файлы, operator feedback. Требует
   подтверждения.
2. **Есть ли верхний предел числа пунктов в панели?** У мастера их девять; даже
   на 2560px это ~800px сплошного текста. Возможно, разумно не показывать больше
   5-6, остальное всегда в «Ещё». Вопрос к дизайну, а не к механике: чистая
   функция примет `maxVisible` без переделки.
3. **Куда переносить переименование кампании** — меню сеанса (дёшево) или
   «Подготовка» (логичнее).
4. **Нужны ли иконки у пунктов.** С иконками пункты уже, влезает больше;
   `@gravity-ui/icons` подключён, но иконок для рабочих пространств в проекте нет.
   Влияет на ширины, не влияет на механику.
5. **Нужен ли гистерезис.** Ответ — по факту ручной проверки на зуме, не заранее.
6. **Переносить ли фокус в первый пункт при открытии «Ещё».** Сейчас
   `.workspace-menu` этого не делает; менять поведение или сохранить — решить
   явно.

## 12. Чего этот план не покрывает

- **Не переводит** «World maps» и «Operator feedback» (UIX-417) и не разводит две
  энциклопедии (UIX-423). Он лишь сводит подписи в один массив, чтобы обе задачи
  стали правкой строк.
- **Не делает мобильную раскладку.** Ниже 960px приложение по-прежнему уезжает в
  горизонтальную прокрутку.
- **Не трогает остальную адаптивность топбара** (переключатель сцен, музыка, меню
  сеанса) — она остаётся на медиазапросах §1.2. Распространить тот же приём на
  весь топбар можно и, вероятно, нужно, но это другая задача и другой объём.
- **Не меняет**, что открывается по пунктам, и не трогает `Sidebar.tsx`.
- **Не содержит чисел «сколько пунктов влезет на 1366px».** Реальные ширины
  подписей не измерялись — в этом и смысл задачи: они считаются в рантайме. Любые
  оценки на глаз в критерии приёмки не выносятся.
- **Не проверено запуском.** План написан по чтению кода; сборка и тесты не
  запускались.

## Три вещи, которые легко пропустить и дорого чинить потом

1. **Кнопка переименования кампании — единственная.**
   `setCampaignRenameOpen(true)` вызывается ровно из одного места
   (`App.tsx:1377`). Убрать `.brand`-блок целиком, не перенеся её, — значит
   удалить функцию, и ни один существующий тест этого не поймает, кроме
   `concept.spec.ts:288`, который проверяет саму иконку, а не наличие функции.

2. **`error-reporting.ts` превращает срыв цикла ResizeObserver в серверный
   отчёт.** Это не косметика — это шум в проде на каждом столе.

3. **У игрока шесть пунктов, а не пять** (§1.1). Если ориентироваться на пять,
   оценка «влезает целиком» окажется неверной ровно на один пункт.
