# Меню и overlay: контракт подключения

UIX-644. Этот контракт развивает UIX-502/517/531, а не объявляет все меню
проверенными. Реестр и границы доказательств выполнения:
[uix-644-menu-inventory.md](plans/uix-644-menu-inventory.md).

## Выбор механизма

1. **Нативные select / color / file:** оставлять браузеру и ОС. Их всплывающие элементы нельзя
   исправить увеличением CSS z-index страницы. Проверять настоящий input,
   доступное имя, ограничения, фокус и событие выбора.
2. **Gravity Select:** использовать `FormSelect`. Владелец поступает через
   `OverlayOwnerContext` под соответствующим `ArkenDialog`, не из внешнего
   замыкания. Прямой Select допустим только с той же обёрткой владельца (как в обратной связи).
3. **Небольшой встроенный details popup:** обязательно `useDismissibleDetails` и
   настоящий ref. Обрезать длинную подпись, **не предка раскрытого popup**.
   Overflow, transform и контекст наложения проверять по всей цепочке предков.
   Если владелец обязан прокручиваться/обрезать содержимое, выбирать портал
   с учётом владельца, а не снимать overflow у всех панелей.
4. **Listbox с одиночным выбором внутри details:** включать опцию `listbox: true`
   только для списка вариантов. Элемент открытия получает `aria-haspopup`, `aria-controls`;
   список — имя/роль и `aria-selected` на вариантах. ArrowUp/Down открывают
   выбранный вариант, Home/End выбирают границу, Escape закрывает и возвращает
   фокус. Выбор возвращает фокус элементу открытия; Tab/выход фокуса закрывает без
   перетягивания фокуса обратно. Не применять навигацию listbox к меню,
   содержащему поля, ползунки и разнородные действия.
5. **Собственный UI упоминаний, контекстных меню, стикеров и ассетов:** зарегистрировать отдельно;
   существование общего hook не доказывает, что такой компонент его использует
   или имеет правильного владельца. Не делать глобальную миграцию без его сценария.

## Слои и жизненный цикл

- Сохранены целочисленные слои: base popup 1000; workspace 1200…1998,
  workspace popup 1999; modal 2000, modal popup 2001. Брать CSS tokens, не
  присваивать случайный больший z-index. CSS-порядок внутри отдельного контекста
  наложения не сравним напрямую с числами вне этого контекста.
- Popup базового экрана не должен появляться над новым модальным окном. Нативные `<details>`
  в потоке (предыстория, ресурсы, секция инициативы) не являются popup и не
  должны закрываться от действий рядом.
- Нажатие снаружи закрывает без кражи фокуса; Escape возвращает фокус своему
  элементу открытия только когда владелец доступен. Произвольная иерархия одновременно
  открытых вложенных модальных окон пока **не выражена уникальным ID владельца** и требует
  отдельной проверки, а не заявления о полной поддержке.
- Для привязанного к viewport встроенного picker предусмотрена включаемая опция
  `closeOnViewportChange`: закрытие при resize/смене compact и прокрутке
  **предка элемента привязки**. Прокрутка списка и соседнего журнала не закрывает меню.
  Это стратегия закрытия, не постоянного перепозиционирования. Она предотвращает
  возвращение устаревшего открытого меню после компактного режима → desktop.
- Listbox ограничивает ширину/высоту реально доступным местом справа/снизу
  элемента открытия. Внутренний список прокручивается; hook не выводит его из контекста владельца.

## Регистрация и проверка

- Новый компонент добавляется в статический реестр вместе с ролью/владельцем,
  цепочкой scroll/overflow и сценарием выполнения. AST-проверка сканирует весь TSX src,
  а не фиксированный список старых файлов. Машинный индекс — средство обнаружить
  изменение поверхности, **не PASS интерфейса**.
- На связанном пуле: реальный hit-test указателя (`elementFromPoint`) и нажатие
  без force; открытие/выбор/закрытие, Escape/возврат фокуса/Tab, повторное открытие,
  смена workspace, viewport/scroll; Chromium и Firefox. DOM `open` и наличие
  списка сами по себе недостаточны.
- Разделять GM/PLAYER, desktop/компактный режим, страницу/workspace/modal/вложенный modal.
  Скрытый устаревший компонент не активировать ради теста. Непроверенный сценарий
  помечать BLOCKED с причиной; новый компонент не наследует чужой PASS выполнения.
- Отрицательный пример должен уронить точную проверку. Сначала сохранить
  исходные байты, после диверсии восстановить в `finally`, затем единый
  восстановленный пул. Не делать общую проверку после каждого метода.

Публикация и production — отдельный этап проверки; этот контракт не разрешает выкладку.
