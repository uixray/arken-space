## Ограничения облачного окружения

| Возможность                     | Статус                                                          |
| ------------------------------- | --------------------------------------------------------------- |
| Vitest, typecheck, lint, build  | доступно                                                        |
| Работа с кодом                  | доступно                                                        |
| Docker multiplayer gate         | **недоступно** — нужен Docker-in-Docker                         |
| Измерения на боевом дампе       | **запрещено** — данные не покидают локальную машину             |
| Browser QA (Chromium + Firefox) | требует PostgreSQL и dev-стенда; проверять доступность на месте |

**Первое действие облачной сессии — инвентаризация окружения**, а не план:
`docker version`, наличие PostgreSQL, установлены ли браузеры Playwright,
работает ли Linear MCP. Отчитаться фактами. Не выдавать недостижимый gate за
пройденный.

## Что работает без `.env`

`.env` в репозиторий не входит (`.gitignore`), и в облачном клоне его не будет.
Это проверено, а не предположено:

- `pnpm install --frozen-lockfile`, `pnpm build`, `pnpm typecheck`, `pnpm lint`,
  `pnpm format:check` и `pnpm test` работают **без** `.env` и без внешнего
  PostgreSQL. Тесты поднимают PGlite в процессе, а не подключаются к базе.
  Полный прогон — 171 файл / 1251 тест.
- `.env` нужен только двум вещам: dev-серверу (`apps/server/src/env.ts`
  требует `DATABASE_URL` и остальные переменные) и e2e, где без
  `GM_ACCESS_TOKEN` часть тестов скипается.
- Проект **не использует dotenv** и не передаёт `--env-file`. Переменные надо
  экспортировать в окружение самому: `set -a; . ./.env; set +a`. Шаблон —
  `.env.example`.

Иными словами, обязательный gate (`build`/`typecheck`/`lint`/`test`) в облаке
достижим полностью. Ограничены только dev-стенд, e2e и multiplayer.

## Ловушка при проверке

`pnpm test:multiplayer` и e2e-обёртки маскируют настоящий код возврата, если
вывод уходит в пайп: процесс завершается нулём, тогда как прогон красный.
Проверять `${PIPESTATUS[0]}`, а не код процесса.
