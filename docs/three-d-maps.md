# Редактируемые 3D-карты

## Архитектурное решение

Отдельный native WebGL viewer выбран для ограниченной клеточной реконструкции.
Он получает те же SceneDto/TokenDto и role-filtered snapshot, что и 2D.
Существующий Konva renderer остаётся отдельной веткой; 3D включается явно,
после просмотра черновика мастером. Внутри 3D доступны обзор и перемещение;
для остальных инструментов включается общий 2D floor-aware editor.

Рассмотренные варианты: Three.js, React Three Fiber и Babylon.js.
Они предоставляют более широкую сценографию/экосистему, чем требуется
процедурным клеточным мешам. В этой реализации ни один из них не добавлен:
нет новой зависимости и её лицензионного включения. Цена native варианта —
собственные матрицы, resource lifecycle, ограниченный импорт и дополнительный
риск ошибок без исполнения. Это не универсальный движок и не Blender.

Одна authority: grid.isometric хранит ярусы, высоты и лестницы;
grid.threeD — reviewed scene spec, клетки, встроенную геометрию декораций
и provenance источников. map3dMovementGeometry выводит blocked из 3D-клеток.
Стены, пустоты, декорации и закрытые двери блокируют ход; открытые двери — нет.
Расстояния, snapping и realtime используют прежние логические клетки,
pixel/top-left размещение токенов и адаптер точки ног.

## Рабочий процесс мастера

1. Создать пустую сцену: занятую 2D-сцену API не переинтерпретирует.
2. В настройках «3D-карта из изображения» выбрать MAP или PNG/JPEG.
3. Указать пикселей/клетку, порог тёмных линий и метров/клетку.
4. Получить предложение, исправить клетки пола/стен/дверей/декораций/пустот.
   Дверям задаётся ось; Shift+клик переключает открыто/закрыто.
   Неопределённые клетки имеют отдельный контур. Комнаты — подсказки flood-fill,
   а не доказательство правильного семантического распознавания.
5. По желанию импортировать ограниченную GLB-геометрию и разместить её клеткой PROP.
6. Просмотреть 3D, подтвердить просмотр планировки и сохранить.
7. Ярусы, blocked и лестницы редактируются существующим графическим редактором.
   Публикация яруса общая для всех игроков; произвольные личные этажи — не эта версия.

Камера: drag orbit, Shift/right drag pan, wheel zoom, «Вписать 3D».
Выбор токена — список; отдельная кнопка включает перенос по плоскости;
WASD использует логические оси. Лестница доступна мастеру при точном совпадении
с её входной клеткой. Сервер проверяет все commit и preview тем же policy.
При потере WebGL или более 512 токенах включается полный 2D-view.
Выбор любого инструмента, кроме PAN, также открывает 2D.

## Повторный импорт и экспорт

Повторное распознавание сохраняет manual-клетки на неизменной сетке;
смена её шага или обрезание ручных клеток отклоняются.
Изменения не становятся сценой до явного save с ревизией. Конфликт ревизий
требует обновить черновик; интерфейс предупреждает о нём.
JSON и GLB выгружаются локально как частные материалы мастера.
JSON импорт принимает geometry + threeD, повторно проверяет schema/budget
и всегда снимает reviewed. Он не загружает внешнее изображение автоматически.

Для агентской оркестрации добавлен локальный runtime-конвертер:

```powershell
pnpm --filter @arken/server map:3d -- C:\maps\input.png C:\maps\draft.json 64 1.5
# Последний аргумент необязателен: существующий JSON для сохранения manual-клеток.
pnpm --filter @arken/server map:3d -- C:\maps\input.png C:\maps\draft-v2.json 64 1.5 C:\maps\draft.json
```

CLI использует уже имеющийся sharp, создаёт только новый частный файл
(wx, без перезаписи). Он сохраняет SHA-256 входных байтов и параметры;
JSON открывается в том же редакторе. CLI-регенерация ограничена одним ярусом;
многоярусные правки выполняются в UI. Порог CLI фиксирован 160.
Браузер использует nearest canvas sampling, CLI — nearest sharp: равенство
результатов на пограничных дробных размерах не заявляется.

## Безопасность и бюджет

- PNG/JPEG до 20 MiB, сторона до 8192, до 16 MP; максимум 128×128 клеток
  в растровом предложении, 16384 клеток суммарно в scene spec.
- Ограниченный GLB 2 до 8 MiB: один embedded buffer, треугольники, POSITION
  float32 и optional unsigned indices, bounded node graph/TRS.
  Внешние URL/buffers, изображения/текстуры, skins, animations, morphs,
  extensions и sparse accessors отклоняются. Материалы не воспроизводятся.
  Основа формата: [официальная спецификация Khronos glTF 2.0](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html).
- Модель нормализуется внутрь одной клетки [0,1]; до 16 моделей и 147456
  position values суммарно, до 1 млн процедурных вершин, один world buffer
  до 24 MB, отдельный actor buffer. Это лимиты, не измеренный расход памяти.
- On-demand redraw, DPR до 1.5 и raster до 1920×1080. FPS не измерен.
- API сохраняет под GM ACL/campaign/revision lock; source asset IDs проверяются
  в той же кампании, asset deletion блокирует используемые 3D-источники.
  Серверу доверяется итоговая разметка GM, не клиентский вывод о правах.
- Player DTO содержит только целиком раскрытые клетки опубликованного яруса,
  их модели с обезличенным именем; source hashes и room metadata исключаются.
  Токены и движения используют существующие published-floor/fog ACL.
- Исходный MAP raster — прежний разрешённый ресурс сессии, а не секретная
  геометрия: нельзя «засекретить» ранее выданный bitmap удалением 3D-клеток.
- SQL 0094 расширяет существующие token/layer guards на THREE_D и проверяет
  соответствие геометрии/blocked при записи сцены, включая другие writers.

## Достоверность и ограничения текущего пула

Уровень свидетельств — только чтение и редактирование исходного кода.
Компиляция, выполнение CLI/SQL/UI, сетевые сессии и измерения не проводились
по указанию владельца. Миграция 0094 подготовлена, не применена; для поставки
нужны согласованные contracts/db/server/web и предшествующие 0092/0093.

Конвертер — грубая luminance-grid сегментация, не CV/AI распознавание
произвольной архитектуры. Тени, подписи, толстая сетка и мебель требуют
ручной коррекции. ISO/perspective art, скрытые этажи и автоматическое
восстановление художественных деталей не поддерживаются. GLB — геометрия
без текстур; свободного перемещения, вращения и масштабирования декораций нет.

Демонстрация на реальной top-down карте и отчёт её качества/времени/правок
остаются открытым критерием задачи. Изометрический арт таверны из прежнего
пула не подходит в качестве такой демонстрации. Стоимость платных API в
данной реализации равна нулю вызовов; фактическое время генерации и стоимость
вычислений не измерялись. Работающий production/приёмка не заявляются.
