# Референсный контент

Материалы мастера, разобранные в машинный вид. Это **не** боевые данные и не
сид. Файл используется только как явный вход review-preview: production server
не читает `docs/content`, а штатный `ensureSeed` не создаёт из него spell pack.
GM может передать содержимое в preview API, проверить результат и сохранить
его отдельной командой только как неизменяемую `REFERENCE`-версию.

## `magic-schools.json`

13 школ магии Аркен-Хара: 145 узлов, 114 связей.

**Откуда взято.** Описания — 13 файлов `.docx` из Eagle-библиотеки
`Arhen Khar.library`. Деревья — скриншоты схем от мастера.

**Чему верить.** Названия, описания, стоимость маны и частота вычитаны из
документов машинно и сверены со схемами: у каждой школы, кроме Воды, число
разобранных узлов совпало с числом узлов на схеме. Связи же **прочитаны со схем
глазами** и требуют подтверждения мастером — линии на скриншотах местами
пересекаются, и ошибка чтения тут не отличима от намерения.

## Что выяснилось при разборе

**Узел бывает пассивным.** У 31 записи нет стоимости, частоты или обеих сразу —
и почти всегда это не пробел в документе, а пассивная способность: «Живучесть»,
«Хладнокровие», «Рожденный в сумраке» просто действуют. Модель обязана
допускать узел без цены и перезарядки, иначе половина «Крови» в неё не влезет.

**Часть узлов не связана ни с чем.** «Армия теней», «Портал», «Буря темных
клинков», «Дежавю», «Повелитель душ» стоят на схемах отдельно. Дерево — это лес,
а не одно связное дерево, и требовать корень нельзя.

**Частота — это не только `DAY`/`BATTLE`/`WEEK`.** В документах встречаются
«1 раз в месяц», «1 раз за игру», «2 раза за партию», «1 в час», «1 в раунд».
Существующий `uses.recharge` их не покрывает — либо расширять перечисление,
либо хранить строкой и не притворяться, что она разобрана.

**Схема и описание местами называют одно разными словами.** Записано в поле
`вариантНаСхеме`:

| В описании                | На схеме             |
| ------------------------- | -------------------- |
| ЭЛЕМЕНТАЛЬ ЛЬДА           | ЛЕДЯНОЙ ЭЛЕМЕНТАЛЬ   |
| АНТИМАГИЧЕСКИЙ УРАГАН     | УРАГАН АНТИМАГИИ     |
| ВОЗДУШНЫЙ ЭЛЕМЕНТАЛЬ      | ЭЛЕМЕНТАЛЬ ВОЗДУХА   |
| ДОПОЛНИТЕЛЬНОЕ ЗАКЛИНАНИЕ | ЗАГОТОВКА ЗАКЛИНАНИЯ |
| ПОРТАЛ (Воздух)           | НЕБЕСНЫЙ ПОРТАЛ      |
| ТЕМНЫЙ ПОРТАЛ (Тьма)      | ПОРТАЛ               |
| МАНТИЯ АНТИМАГА           | МАНТИЯ АНТИМАГИИ     |

Канонической выбрана версия из описания — там же лежит текст способности.

**Опечатки в названиях исправлены по указанию мастера**: «ДЕМОНИЧЕСКОЕ УИЛЕНИЕ»
→ «УСИЛЕНИЕ», «ВЕРЕМЕННОЙ КОЛОДЕЦ» → «ВРЕМЕННОЙ», «ВОССТОНАВЛЕНИЕ МАГИИ» →
«ВОССТАНОВЛЕНИЕ». Правка затронула и связи, ссылавшиеся на прежние написания;
висячих рёбер после неё не осталось. В исходных `.docx` опечатки на месте —
повторный разбор их вернёт, поэтому правка живёт здесь, а не в импортёре.

**У Воды нет схемы** — 11 узлов есть, связей нет вовсе.

**«1. Вода.pub»** — файл Microsoft Publisher, читается плохо; взят `.docx`-дублёр
из соседней папки.

## Список нерешённого

Поле `требуетУточнения` в JSON — 31 запись без стоимости или частоты. Разобрать
их вместе с мастером: пассив это или пропуск в документе. Импорт сохраняет
каждую запись как структурированный `OPEN` warning. Пока хотя бы один warning
не закрыт новой проверенной версией, отдельная GM-команда promotion в `ACTIVE`
завершается ошибкой и не создаёт версию или audit event.

## `world-artbook.json`

78 записей канона мира для энциклопедии (UIX-263): 13 богов, 29 локаций,
28 персонажей, 8 существ.

**Откуда взято.** Тексты (имя и краткое описание) — артбук на Framer
(`https://arc.framer.photos/`, legacy), получены 22.10.2026. Новый источник
`https://arken-khar.tilda.ws/` — лендинг романа: энциклопедических записей в
нём нет, имена героев совпадают с артбуком (Кай = Кайзер Астер), поэтому
конфликтов источников нет. Картинки — экспорт Eagle-артбука владельца; в JSON
лежат только относительные пути `Раздел/файл.png`, сами файлы в репозиторий
не входят.

**Права и редактура.** Владелец подтвердил права 22.10.2026
(`rightsReviewStatus: APPROVED`). Импорт создаёт только DRAFT
(`editorialApprovalStatus: PENDING`): мастер дописывает тексты и публикует.
У каждой записи есть `sourceUrl`, `rawContentHash` (sha256 имени и описания)
и атрибуция.

**Импорт (частичный этап UIX-263a).** В менеджере сущностей мира мастер
сначала строит preview: отсутствующие записи предлагаются к созданию, точное
совпадение источника и текста помечается как уже совпавшее, любое расхождение
или не-DRAFT запись блокируется для importer-записи. Только после явного
подтверждения создаются отсутствующие DRAFT с editorial PENDING. Повторный
preview не перезаписывает изменённый или чужой канон. Checksum текста — это
SHA-256 имени и описания, а не исходного HTML/документа.

Загрузка изображений — отдельное необязательное подтверждение. UI показывает
точный относительный путь, цель, роль и SHA-256 исходных выбранных байтов;
путь является предложением сопоставления, не Eagle ID или доказательством
происхождения. Неоднозначные и повторно используемые пути блокируются.
Сопоставление «Теневая башня» → «Темная башня.png» показано как исключение
мастера и требует явного подтверждения. Отчёт различает пропущенные,
заблокированные и неуспешные элементы и показывает полученный asset ID, если
upload завершился, но ссылка не подтверждена. Upload и привязка — отдельные
транзакции; атомарность и сохранение image checksum в записи канона не
заявляются. Повтор с теми же кампанией, источником, путём и байтами использует
ту же identity для безопасного replay, без автоматического удаления ассета.
Перед upload выполняется read-only поиск сохранённой upload identity и сверка
полного выбранного набора с текущими cover/gallery; известный чужой или ручной
медиа-конфликт не вызывает новый upload. Для галереи сервер атомарно проверяет
DRAFT, revision и точный source/text под блокировкой строки в транзакции
привязки. Это гарантирует состояние на момент attach, но не мешает мастеру
опубликовать запись позже и не делает upload+attach одной транзакцией.

Этот ограниченный этап не закрывает все AC UIX-263: исходные HTML/Eagle IDs,
полная сверка источников и устойчивый исторический media inventory требуют
отдельной проверки мастером. Подтверждённые 22.10 права не запрашиваются
повторно. Исходные файлы не изменяются.

**Уточнить.** «Теневая башня» сопоставлена с файлом «Темная башня.png» по
смыслу. Семь картинок без текста (`картинкиБезТекста`) записями не стали.
