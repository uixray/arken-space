## Как не делать работу дважды

В этой сессии часть UIX-518 была сделана дважды: параллельная облачная сессия
уже реализовала изоляцию состояния, а здесь независимо чинилась та же задача.
Причина простая — **перед началом работы не проверялись открытые PR и ветки**.

Правило на будущее, для любой сессии:

```sh
gh pr list --state open
git ls-remote --heads origin | grep -v codex/
```

Если по задаче уже есть ветка или PR — продолжать её, а не начинать заново.
Linear-статус этого не показывает: задача остаётся In Progress, пока PR висит
непринятым.

Второе: не запускать две сессии на одну область одновременно. Разделять по
задачам, а не по времени.
