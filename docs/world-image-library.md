# Независимая библиотека иллюстраций мира

## Постоянные страницы

Статьи открываются по `/campaign/<UUID>?article=<UUID>`. Связанные материалы
имеют обычные ссылки, поддерживают открытие в новой вкладке; браузерная история
и reload сохраняют выбранную статью. После входа разрешён возврат только к
валидной кампании и одному UUID статьи, без произвольных внешних URL, hash или
других query-параметров. Адрес статьи не предоставляет дополнительных прав:
все detail/media/relation запросы по-прежнему проходят серверную видимость.
Несуществующее, скрытое и некорректное открываются как недоступная статья.

## Владение и сохранность

`world_content_images` не имеет внешнего ключа на кампанию, membership или asset.
Обложка и галерея канонической статьи ссылаются на эту библиотеку, а не на
удаляемую строку `assets`. UUID, имя, storage key и параметры файла фиксируются
при первом прикреплении. Замена файла исходной кампании не переписывает ранее
выбранную каноническую иллюстрацию: для новой версии используйте новый asset.

Бинарный файл хранится один раз. Библиотека становится самостоятельным владельцем
того же неизменяемого blob; это не зависящий от кампании указатель на её metadata.
Удаление/замена campaign asset сохраняет blob, если он закреплён библиотекой.
Удаление кампании каскадно удаляет её metadata, но не библиотечные строки,
обложки или галереи. Портреты отдельных экземпляров кампании остаются её данными.

Удаление изображения из галереи или удаление статьи не удаляет его из общей
библиотеки. Автоматического удаления library blobs в этой версии нет. Любой
будущий файловый GC обязан учитывать `world_content_images.storage_key`, а не
только `assets`. Ручное удаление файлов на диске не защищается DB-ссылками.

## Доступ и повторное использование

В редакторе мастера доступны отдельные раскрывающиеся библиотеки для выбора
обложки и изображения галереи. Каталог постраничный, до 50 строк; есть обновление
и повтор загрузки. Сам каталог и его thumbnail endpoint доступны только GM,
как и существующий общий редактор канона. Независимого player-каталога нет.

Игрок получает изображение только через `/api/world-content/:id/images/:imageId/content`:
сначала проверяется видимость статьи для текущей кампании, затем фактическая
принадлежность изображения её обложке/галерее. Неизвестное и недоступное дают
одинаковый 404. Storage keys не возвращаются. Ответы private/no-store и nosniff.
В image URL передаётся campaign ID текущего маршрута; другая shared-cookie
кампания не может незаметно подменить контекст этого запроса.

Ссылки на канонические иллюстрации больше не делают исходный campaign asset
видимым игроку через snapshot. Это существенно при замене исходного файла:
новое содержимое private asset не становится опубликованным вместе со старой
канонической иллюстрацией.

## Миграция и выпуск

`0090_world_content_images.sql` копирует metadata уже прикреплённых иллюстраций,
сохраняя IDs и порядок галерей, переключает два FK на библиотеку и устанавливает
триггеры фиксации новых ссылок. Первая фиксация блокирует строку asset на время
копирования metadata, сериализуя её с удалением/заменой. Файлы не перемещаются
и повторно не кодируются; источники, attribution и редакционные решения статьи
не меняются. Migration journal содержит новый этап idx90 после existing idx89.

Миграция в этом пуле только подготовлена локально. Код сервера, веба и schema
следует выпускать согласованно: старый API после этой миграции может применить
устаревшее удаление ссылок/файлов. Откат на такой API без совместимой доработки
небезопасен. Обратное восстановление старых FK допустимо только при наличии
исходных assets для всех library references; удалённые кампании нельзя выдумывать
или восстанавливать автоматически ради прохождения FK.

Новые runtime, migration и browser прогоны по запросу владельца не запускались.
Исторические проверки каскадного удаления относятся к прежнему контракту:
отсоединение обложки и исчезновение галереи больше не являются ожидаемым
поведением канонических иллюстраций. Новых PASS или доказанной проверки rollback нет.
