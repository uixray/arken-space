# UIX-708 — источники полных рассылок

## Статус и назначение

02.11.2026: подготовлены **локальные исходники выключенной диагностики**.
Код отчёта, сервер и измерения в этом этапе не запускались. Это не оптимизация,
не измеренный выигрыш и не выполнение acceptance UIX-708.

Исходное условие UIX-708: менять редкие домены на точечные события только после
измерений заметной нагрузки. Старый `[snapshot-metrics]` содержал размер/время
рассылки, но не источник её запроса. Сохранённый операционный отчёт UIX-407
показывал idle-вкладку, а не стоимость инициативы, видимости, размера или сцен.
Клиентский heartbeat подтверждает поступление метрик, но не отвечает на этот вопрос.

Расширен существующий флаг `ARKEN_SNAPSHOT_METRICS=1`, который остаётся выключенным
по умолчанию. Конфигурация окружения, compose, workflow и production не изменены.
Запуск измерений/проверок и включение флага требуют отдельной команды владельца.

## Что изменено

- `apps/server/src/snapshot-metrics.ts`: фиксированный словарь модулей и сборщик
  запросов до фактического старта coalesced-рассылки.
- `apps/server/src/routes.ts`: метки в существующих callback, перенос накопленного
  набора при старте и безопасная проекция v2 в существующий диагностический stdout.
- `scripts/report-snapshot-metrics.mjs`: отдельный offline-отчёт из **одного явно
  указанного** файла; не импортирует сервер, не подключается к БД/сети, не ищет
  журналы и не создаёт файлы. JSON выводится в stdout.

`broadcast-coalescer.ts`, wire-контракты, ACL, проекции видимости, маршруты команд,
порядок `settled`, reconnect и клиентская телеметрия не изменены.
При выключенном флаге сборщик даже не создаётся; используется прежний callback.

### Метки источника

Это **модуль, запросивший рассылку**, а не доказательство, что именно его данные
занимают всё время/байты снапшота. Например, `character-play` не различает каждую
операцию инициативы/кошелька; `token` — размер и видимость. Для дальнейшего решения
нужен записанный сценарий, а при смешанных командах — более узкий разрешённый замер.

| Метка               | Источник                                |
| ------------------- | --------------------------------------- |
| `world-map`         | Мировая карта                           |
| `progression`       | Прокачка                                |
| `character-extras`  | Дополнительные поля персонажа           |
| `awards`            | Награды и привязки                      |
| `character-archive` | Архив персонажей                        |
| `encounter`         | Encounter-модуль                        |
| `economy`           | Магазины                                |
| `asset-lifecycle`   | Жизненный цикл медиа                    |
| `campaign-pause`    | Актуальное состояние перерыва           |
| `membership-rename` | Переименование участника                |
| `character`         | Основные команды персонажа              |
| `scene`             | Сцены                                   |
| `token`             | Команды токенов, оставшиеся на snapshot |
| `canvas`            | Канвас, включая undo/redo               |
| `sticker`           | Штампы                                  |
| `campaign`          | Настройки кампании                      |
| `character-play`    | Игровые команды персонажа               |
| `asset`             | Основные команды медиа                  |
| `drawing-fallback`  | Явный fallback рисунка к snapshot       |
| `unattributed`      | Источник не указан/не входит в словарь  |

Метки не принимаются из HTTP-параметров или игровых значений. Независимый CLI
имеет такой же allowlist; при добавлении метки обновлять оба словаря.

## Объединение запросов и стоимость

1. Каждый вызов broadcast добавляет метку **до** вызова существующего coalescer.
2. Запущенный callback синхронно забирает и удаляет накопленный набор, ещё до
   `fetchSockets`/БД. Новые вызовы относятся к следующей рассылке.
3. Вызовы, присоединившиеся к уже ожидающему callback, тоже учитываются, хотя их
   собственный callback не запускается. Очередь и её promises не заменены.
4. Итоговая запись представляет одну успешную рассылку, а не каждую команду.
   `requestedCalls` — число запросов; `counts` — их распределение по источникам.
5. Ограничение счётчика — 1 000 000 вызовов на набор. При превышении выставляется
   `truncated`; такой набор не считается полностью атрибутированным.

Отчёт относит стоимость каждой записи ровно в одну группу:

- `single-domain`: известен один модуль;
- `mixed`: несколько известных модулей;
- `unattributed`: отсутствует набор либо есть неизвестный источник;
- `truncated`: неполная атрибуция из-за ограничения счётчика;
- `legacy`: прежний формат без меток.

Для mixed стоимость **не копируется на каждый домен и не делится пропорционально
числу вызовов**. Суммарные байты групп равны байтам принятых записей. Отдельные
`observedTriggerRequestsByDomain` — только счётчики запросов, не распределение затрат.

## Формат, границы и приватность

v2: `schemaVersion`, `recordedAt` (UTC), `triggers` (scope `ROUTE_MODULE`, counts,
requestedCalls, truncated), существующие числовые sockets/queries/bytes/ms,
размеры по полям и числовые измерения проекций с ролью.
Новая stdout-проекция исключает campaignId и любые ID участников/запросов/сущностей.
Старые сырые журналы могут содержать campaignId: не считать их анонимными.
CLI возвращает только известные метки, числа и допустимые timestamps; не возвращает
сырые строки, имена файлов, идентификаторы, роли, произвольные поля или ошибки JSON.

Ограничения доказательств:

- Измеряются успешные рассылки через `broadcastSnapshots` в `routes.ts` с получателями.
  Пустые комнаты, ошибки, другие пути отправки, начальное подключение и reconnect
  не создают записи здесь. По отчёту нельзя посчитать все команды/весь трафик.
- `totalBytes` — размер JSON до socket-протокола и сжатия, не фактический сетевой
  трафик и не подтверждение получения клиентом.
- `totalMs` начинается после поиска сокетов; очередь coalescer не входит.
  Время включает общий read set, построение и накладные расходы диагностики;
  это не задержка интерфейса, не CPU time и не стоимость выключенного режима.
- Сумма длительностей может перекрывать одновременную работу кампаний и не равна
  времени наблюдения. Диапазон timestamps тоже не доказывает непрерывное покрытие.
- `queries` — process-window estimate с параллельными запросами. CLI намеренно
  не суммирует и не приписывает этот счётчик доменам.
- Логи не имеют уникальных ID записей и не доказывают revision. Нужен один
  неперекрывающийся capture с отдельно записанными SHA/dirty scope, сценарием,
  периодом и числом подключённых клиентов. Повторный импорт удвоит записи.
- Ноль пригодных записей означает **нет данных**, а не отсутствие нагрузки.

## Будущий разрешённый запуск отчёта

После отдельного разрешения и получения capture, из корня checkout:

```powershell
node scripts/report-snapshot-metrics.mjs 'D:/path/to/private/server-capture.log'
```

Поддерживается сырой stdout Node либо префикс UTC от `docker logs --timestamps`.
Compose/service prefixes не удаляются произвольно: строки с неизвестным префиксом
считаются отдельно, а не молча принимаются за измерение. BOM первой строки допустим.
JSON с неизвестной версией, неверными числами/метками/суммами или строка больше
65 536 символов отвергается. Текст отвергнутых строк не выводится.
Код 0 — файл разобран, **не PASS производительности**; 2 — нет данных или есть
отвергнутые/неподдерживаемые строки; 1 — ошибка вызова/чтения/агрегации.
Отчёт не включает флаг и не снимает замеры сам.

## Что ещё нужно для UIX-708

1. Отдельно разрешённый связанный прогон диагностики/отчёта: флаг off/on, один
   вызов, много однодоменных, mixed, независимые кампании, ошибка текущей рассылки,
   пустая комната, граница усечения, legacy/повреждённые/чужие строки и приватность.
   Проверить неизменность coalescing/settled/reconnect и нулевой сбор при off.
2. Репрезентативные измерения редких действий на зафиксированной версии и сценарии;
   до них нельзя утверждать, что конкретный домен тормозит или что нужна конверсия.
   Изолированный `measure-broadcast.ts` по-прежнему нельзя запускать на production:
   его snapshot-путь может выполнять нормализацию с записью в БД.
3. Только при подтверждённой значимости — согласованный перевод доменов, каждый
   отдельным коммитом с проверкой видимости и негативным контролем по исходным AC.
   Канонический reconnect обязателен. Текущий source-only этап эти AC не заменяет.

Ни один из этих прогонов в текущем этапе не выполнен. Существующие данные UIX-407
не были переименованы в доказательство UIX-708.
