# Capability Experiment Review — Июль 2026

**Связанная задача:** [UIX-249]
**Статус:** Завершённый разбор
**Контекст:** Оценка возможностей конкурентов (от 20 июля 2026) на предмет применимости в Arken Space.

## 1. Текущие возможности Arken Space (на момент проверки)

- **Базовый игровой контур:** Карты, токены, туман войны, чат, popup-окна.
- **Взаимодействие:** Броски кубов прямо из карточки персонажа, общий контроллер карты (мышь, touch, клавиатура).
- **Чего пока нет:** Полноценной системы заметок, энциклопедии мира, глубокой интеграции с мобильными устройствами (кроме базового touch-ввода), адресных handouts.
  _(Источник: `ROADMAP.md` и открытые задачи в Linear)_

## 2. Оценка кандидатов

Ниже приведён разбор идей из конкурентного исследования.

| Кандидат                                           | Статус в Arken Space    | Решение      | Обоснование                                                                                                                                                               |
| -------------------------------------------------- | ----------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Подготовка сцены как шаблона                       | Missing                 | Deferred     | Высокая полезность, но пока избыточно для текущего фокуса на стабильности ядра. Основной риск — утечка приватных данных при копировании сцены.                            |
| **Private handouts и GM notes с адресной выдачей** | Missing                 | **Selected** | Критично для жанра TRPG. Требует строгой server-side visibility, но это совпадает с архитектурой Arken Space. Сценарная частота: высокая.                                 |
| **Мобильный companion для игрока**                 | Partial (touch support) | **Selected** | Полноценный canvas на мобильном устройстве (non-goal) не нужен, но companion для бросков и просмотра листа персонажа снимет необходимость открывать ноутбук всем игрокам. |
| Импорт с предварительным просмотром и provenance   | Missing                 | Deferred     | Важно для авторских прав (provenance), но текущий процесс загрузки медиа пока удовлетворяет базовые нужды. Отложено до следующего пересмотра хранилища ассетов.           |
| **Сохранённые пресеты бросков и быстрых действий** | Missing                 | **Selected** | Повысит удобство игроков, избавляя от необходимости открывать карточку персонажа для частых действий. MVP не требует языка скриптов.                                      |

Отклонённые/отложенные кандидаты из списка "Evaluate next / Later" (Spectator режим, сценарный чек-лист, импорт внешних персонажей, полуавтоматическая видимость) пока признаны избыточными или несущими высокие риски усложнения продукта (scope creep).

## 3. Выбранные Discovery-эксперименты

### Эксперимент A: Мобильный companion для игрока

- **Целевой пользователь:** Игрок (не GM).
- **Сценарий:** Игрок участвует в сессии с телефона, бросает кубы, читает чат и смотрит характеристики, пока GM двигает токены на большом экране.
- **Пользовательская ценность:** Высокая (освобождает пространство, снижает барьер входа).
- **Стоимость реализации:** Medium.
- **MVP:** Адаптивные экраны (Лист персонажа, Чат, Броски, read-only сцена). Без редактора canvas.
- **Explicit Non-goals:** Полноценный мобильный VTT с редактированием, инструментами мастера и сложным туманом войны на мобильном.
- **Метрика успеха:** Игрок может провести сессию без необходимости открывать десктопную версию.
- **Stop condition:** Ограничения производительности мобильных браузеров на рендеринге даже read-only сцены.
- **Риски:** Accessibility на малых экранах; размывание фокуса разработки.
- **Зависимости:** Существующая touch-навигация, адаптивный UI.

### Эксперимент B: Private handouts с адресной выдачей

- **Целевой пользователь:** GM.
- **Сценарий:** GM отправляет текстовую улику или изображение конкретному игроку или группе, скрывая её от остальных.
- **Пользовательская ценность:** Высокая (секреты и личные квесты).
- **Стоимость реализации:** Medium/Large (зависит от сложности server-side visibility).
- **MVP:** Карточка текста/медиа с выбором получателей; возможность отзыва доступа.
- **Explicit Non-goals:** Сложная иерархия папок для заметок; публичный шаринг вне текущей сессии.
- **Метрика успеха:** Игроки видят только предназначенные им handouts, что подтверждается сервером (разные snapshot-данные).
- **Stop condition:** Утечка данных через клиентское состояние (нарушение server-side visibility).
- **Риски:** Безопасность данных, усложнение модели прав.
- **Зависимости:** Надежная подсистема управления правами (ACL) на стороне сервера.

### Эксперимент C: Сохранённые пресеты быстрых действий

- **Целевой пользователь:** Игрок, GM.
- **Сценарий:** Нажатие одной кнопки для частого броска (например, атака основным оружием) без поиска по листу персонажа.
- **Пользовательская ценность:** Средне-высокая (ускоряет ход боя).
- **Стоимость реализации:** Medium.
- **MVP:** Сохранение ограниченного набора валидных выражений для бросков (roll macros) без возможности писать произвольный код.
- **Explicit Non-goals:** Полноценный язык скриптов, API для модов, маркетплейс макросов.
- **Метрика успеха:** Уменьшение времени на заявку действия игроком.
- **Stop condition:** Потребность игроков в Turing-complete языке макросов для базовых нужд.
- **Риски:** Рассинхрон между сохранённым действием и обновлёнными параметрами персонажа.
- **Зависимости:** Существующая система парсинга бросков.
